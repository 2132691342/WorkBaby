# 02 · 数据模型

存储为单文件 SQLite（`{home}/db/workbaby.db`，WAL，连接数固定 1）。业务表由 `db.Migrate` 的 AutoMigrate 维护（26 张），FTS5 虚拟表单独建（`db.CreateFTS5`）。

## 约定

- 主键一律字符串 ID：`pkg.NewID("前缀")` 生成 `前缀_ULID`（同毫秒自增熵，天然按时间有序）
- 时间字段统一 `int64` 毫秒：`autoCreateTime:milli` / `default:0`
- JSON 字段以 `...JSON` 结尾存文本（如 `MetadataJSON`、`ToolCalls`）
- 软删：仅 `knowledge_docs` 用 `gorm.DeletedAt`，其余物理删除
- DO 定义在 `internal/domain`，访问在 `internal/repo`，两者一一对应

## 状态机

**消息** `MessageStatus`：`pending → streaming → completed / failed / cancelled → archived`

**停止原因** `StopReason`：`completed / cancelled / max_turns / tool_error_limit / token_budget / stagnation / error`
由内核 Reason 映射（`MapHarnessReason`）：`end_turn→completed`、`cancelled→cancelled`、`max_turns→max_turns`、`max_tokens|budget_exceeded→token_budget`、其余 `error`。

**审批** `ApprovalStatus`：`pending → approved / denied / timeout / cancelled / answered / skipped → consumed`
`consumed` 表示已被续跑链路消费，防止一次性审批被静默复用。

**后台任务** `TaskState`：`pending → running → completed / failed / cancelled`

**知识文档**：`pending → parsing → indexed | failed`

**运行记录**：`running → done / error`

**执行平面** `core.Scope`：`chat_turn / task / tool_only / delegate`；`ExecutionState`：`planning / running / paused / waiting_input / completed / failed / cancelled`

**用量来源** `UsageSource`：`chat / memory / delegate / task`——委派与后台任务的消耗单独归因，不混进对话成本。

## 关键字段

**ChatSessionDO**：`ProviderID / Model / WorkspacePath / PermissionMode / Kind(normal|side) / ParentID / Pinned / MessageCount / MetadataJSON`
目标模式、压缩边界等会话级状态都存在 `MetadataJSON` 里，避免为每种状态加列。

**MessageDO**：`Seq`（会话内单调，工具消息与注入消息统一分配）、`RunID`、`Role(user|assistant|tool|system)`、`ToolCallID`、`ToolCalls`、`Status`、`StopReason`、`Input/Output/CacheRead/TotalTokens`、`LatencyMs`、`Cost`、`ContextScope(llm|ui)`

**TokenUsageDO**：`Source / Agent / Turn`——`Turn = -1` 表示非对话轮次（委派、后台任务）。

**ApprovalRecordDO**：`Kind(approval|input)`、`Command`（审批卡片展示与免审匹配都用这个）、`Risk`、`ExpiresAt`（启动重武装延长到 24h）

**ChatTaskDO**：`SessionID`（宿主会话：工作区与模型来源）、`Agent`、`Prompt`、`State`、`RunID`、`Result`、`Error`

## 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 单文件 SQLite + 连接数固定 1 | 零部署、无写锁竞争、行为可预测（桌面单用户最优） | 并发写串行；长查询会阻塞写入 |
| 字符串主键（`前缀_ULID`） | 天然按时间有序、跨表可读、前端可直接展示 | 比自增整数占空间；索引体积略大 |
| 毫秒时间戳 int64（不用 `time.Time`） | 跨边界（JSON/SQLite/前端）零转换、排序直接可用 | 需要自行格式化显示；无时区信息（本地单机可接受） |
| JSON 字段存文本（`MetadataJSON` / `ToolCalls`） | 会话级状态不必为每种加列（目标模式、压缩边界都收在里面） | 无法用 SQL 直接过滤这些字段；结构变更靠代码兼容 |
| FTS5 trigram 分词 | 中文可检索（unicode61 会把整句中文退化成单 token） | 短于 3 字的查询零命中，必须由调用方子串兜底 |
| 检查点每 run 只留最新一轮 | 存储恒定、写入廉价、不会随长 run 膨胀 | 无法回放到更早轮次 |
| 审批记录持久化 + `consumed` 标记 | 跨重启不丢决策；一次性审批不会被静默复用 | 多一张表与一套恢复逻辑 |
| 用量按来源拆分（`UsageSource`） | 委派/后台任务成本可单独归因，不混进对话账单 | 每个记费点都要正确标注来源 |
