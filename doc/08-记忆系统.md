# 08 · 记忆系统

设计取舍：**不做情景/语义/程序分类，也不做 run 后自动沉淀**。长期记忆就是一份人能直接编辑的 Markdown 文件，FTS5 只是它的派生索引。

## 存储

单一真相源：`{home}/memory/{sessionID}/MEMORY.md`（会话绑定工作区时放在 `<工作区>/.workbaby/memory/{sessionID}/`）。

```markdown
# 长期记忆

## 用户偏好
- 回复用中文

## 事实
- 项目用 Go 1.24

## 流程
- 提交前跑 go test ./...

## 项目约定
- 错误码按段位分配
```

四个固定分节：用户偏好 / 事实 / 流程 / 项目约定；未知分节归一到「事实」。
上限：200 条（写满丢最旧一条），单条 400 rune；重复条目幂等跳过。

## 写入时机

1. 模型通过 `memory_write` 工具主动追加（唯一由 Agent 触发的写入路径）
2. 设置页的增删与整篇覆盖

刻意不做 run 后自动抽取：自动沉淀会把噪声写进记忆，且难以修正。要记住什么由用户或模型明说。

## 检索

FTS5 虚拟表 `memory_fts(section, content, tokenize='trigram')`，全量重建（事务内删旧插新）。

查询：`MATCH` + `bm25` 排序；查询串按词加引号以 OR 连接；短于 3 字（trigram 窗口）的查询退化为子串扫描。

打分不是 bm25 原值，而是名次递减（`len(rows) - idx`）；兜底子串打分 = 命中次数×10 − 文本长度/100。

## 注入

能力注册表在 run 前按用户输入检索（`Search(input, 6)`），命中则作为 Section 注入（Order 40，Title 提示可用 `memory_write` 追加）；无命中时回退全文并截断到 4000 rune。

记忆开关在设置页（`system_settings` 的 `SettingKeyMemoryEnabled`），关闭后不注入也不暴露 `memory_write`。

## 与知识库的区别

| | 记忆 | 知识库 |
|---|---|---|
| 内容 | 简短、稳定、关于用户与项目的事实 | 长文档 |
| 写入 | 逐条追加 | 文档级导入（文件/URL/文本） |
| 检索单位 | 条目 | 分块（500 字，重叠 50） |
| 归属 | 会话 | 全局 |

## 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 单一 MEMORY.md（人可读可改）+ FTS5 派生索引 | 数据可迁移、可手工修正；索引丢了重建即可 | 无向量语义检索（靠 FTS + 短查询子串兜底） |
| 条目上限自收敛（写满丢最旧） | 注入段不会无限膨胀 | 早期条目会被挤掉（重要内容需用户手动固化） |
| 会话级归属 | 不同项目的记忆互不串味 | 跨会话的通用偏好需重复记录（或沉淀成全局规则/技能） |
| run 后异步沉淀（独立超时） | 不阻塞响应；形成记忆失败不影响对话 | 沉淀时机不是即时的（下一轮才可用） |
