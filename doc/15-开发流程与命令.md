# 15 · 开发流程与命令

## 常用命令

| 目的 | 命令 |
|---|---|
| 开发运行 | `wails dev` |
| 后端全量测试 | `go test ./...` |
| 单包测试 | `go test ./internal/service -run TestXxx -v` |
| 编译检查 | `go build ./...` |
| 前端类型检查 | `cd frontend && npm run typecheck` |
| 前端测试 | `cd frontend && npm run test` |
| 前端构建 | `cd frontend && npm run build` |
| 分层门禁 | `pwsh scripts/check-boundaries.ps1` |
| 契约门禁 | `pwsh scripts/check-contract.ps1` |
| i18n 校验 | `node scripts/i18n-sync.mjs check` |

## 门禁脚本

四个脚本，改完代码跑一遍即可发现越界与漂移：

| 脚本 | 检查什么 |
|---|---|
| `scripts/check-boundaries.ps1` | 分层依赖：`pkg` 不依赖 internal、`domain`/`repo` 不反向依赖、`api` 不直接 import repo、`service` 不含 HTTP、`core` 不依赖上层也不含 HTTP；外加前后端契约版本号一致 |
| `scripts/check-contract.ps1` | 路由约定（cancel 与 resume 必须分路径）+ 前端 `client.ts` 的路径白名单必须与后端 `routes_*.go` 注册前缀一致 |
| `scripts/i18n-sync.mjs` | zh / en 字典键集合与顺序一致；`dead` 子命令找未被引用的死键 |
| `scripts/copy-runtimes.ps1` | 构建后钩子：内置运行时归档必须齐全 |

`scripts/test.ps1` 是分层测试入口：`-Pkg service`、`-Run TestXxx`、`-NoFront`、`-Full`。`-Full` 会跑全部 Go 包 + 分层门禁 + i18n 校验 + 前端类型检查与测试。

## 测试策略

只保留有诊断价值的测试：**跨层链路、复杂场景、易静默失效的契约**。纯 CRUD 往返、getter 之类的单测不保留。

| 层 | 覆盖重点 |
|---|---|
| `internal/core` | ReAct 循环、护栏链裁决语义、压缩后工具配对、上下文优先级裁剪 |
| `internal/service` | 会话编排链路、审批暂停恢复、后台任务状态机、安全与信任、用户钩子子进程协议、跨模块链路（MCP 加密、文件变更与回滚） |
| `internal/llm` | 三家协议解析 + 一致性契约（错误分类、重试、参数优先级） |
| `internal/server` | SSE 重放 / gap / 慢客户端 |
| 工具与运行时 | exec 解析、文件守卫（gitignore、写前必读）、解压路径穿越与限额 |
| 前端 | 流事件管线、消息对账（重影/堆叠/丢增量）、块分组、命令参数展开 |

新增功能时，优先写一个覆盖完整链路的测试，而不是为每个函数写一条断言。

## 改动规范

分层、错误码、命名、注释与文档要求见仓库根 [CLAUDE.md](../CLAUDE.md)。要点：

- 新增后端端点：改 `internal/server/routes_<域>.go` + `internal/api/api_<域>.go`，业务进 `service`；同时更新 `doc/16-API契约总表.md` 与前端 `client.ts` 白名单
- 新增表：加 `domain` DO → 加 `repo` → 登记 `db/migrate.go` → 更新 `doc/02-数据模型.md`
- 新增工具：实现 `tool.Tool` → 在 `api.Handler.Startup` 注册 → 更新 `doc/05-工具系统.md`
- 新增文案：zh / en 字典同步加键，跑 `i18n-sync.mjs check`
- 文档与代码必须同时更新：文档描述设计意图与当前实现，不记录改动过程
