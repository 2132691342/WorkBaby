# 18 · 测试体系

## 定位

测试只守护**跨模块 / 跨轮次 / 跨协议**的行为：一个测试失败，必须意味着某条真实链路坏了。
纯函数、CRUD、字段映射、枚举转换、构造冒烟一律不写测试——它们改动频繁、失败信息无价值，
只会拖长每次验证的时间与阅读成本。

## 分层与职责

| 包 | 测什么 | 代表文件 |
|---|---|---|
| `internal/core` | ReAct 多轮循环、护栏链裁决、压缩不拆散 assistant+tool 对、历史清洗 | `loop_test.go` `guard_test.go` `context_test.go` |
| `internal/service` | 编排链路：装配接线、事件映射、审批与续跑、检查点、集成编排（文件变更/反爬/反幻觉） | `chat_test.go` `recovery_test.go` `event_mapper_test.go` `integration_test.go` |
| `internal/llm` | 跨 Provider 归一化契约（错误分类、重试退避）+ 三家线协议流解析 | `conformance_test.go` `*/client_test.go` |
| `internal/tool` | 工具落点与沙箱（绑定目录后相对路径不得落到默认根）、写前必读护栏、计划模式硬拦 | `workspace_link_test.go` `file/guard_test.go` `planmode/planmode_test.go` |

## 文件索引（怎么快速找到该跑哪个）

| 改动面 | 跑这个 |
|---|---|
| 内核循环 / 护栏 | `go test ./internal/core/` |
| 聊天编排 / 审批 / 恢复 | `go test ./internal/service/ -run 'TestChat|TestApproval|TestDurable|TestCheckpoint'` |
| 事件契约 | `go test ./internal/service/ -run TestCoreEventMapper` + `-run TestEmitterContract` |
| SSE | `go test ./internal/server/` |
| 模型接入 | `go test ./internal/llm/...` |
| 工具沙箱 | `go test ./internal/tool/...` |

## 关键设计

**1. 场景函数 + 父测试聚合（service 层）**

`chat_test.go` 把场景写成私有函数（`testApprovalScopes`），由父测试用 `t.Run` 聚合：

```go
func TestChatApproval(t *testing.T) {
	t.Run("scopes", testApprovalScopes)
}
```

好处：改某个能力只需跑对应的一个父测试（`-run TestChatApproval`）；场景函数可被多个父测试复用；
单文件测试函数数受控（≤6）。

**2. 真实依赖优先，只在必要处用替身**

- 数据库用真实 SQLite（内存模式 + 真实迁移），不用 mock repo——迁移与 FTS5 是高频故障源；
- LLM 用 `stubProvider`（按调用序返回预设响应），因为它跨进程且不可控；
- MCP 用**真实子进程** fixture（同一测试二进制 re-exec 成 server），因为要测的就是进程协议。

**3. 守卫不稳定的外部依赖**

依赖系统 shell / 真实网络的用例先 `exec.LookPath` 或 `testing.Short()` 判断后跳过，
不得让整个包变红。

## 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 只测复杂链路 | 全量测试 10 秒内跑完；失败信息直指真实故障 | 简单函数的回归靠编译期与集成测试兜底 |
| 私有场景函数 + `t.Run` 聚合 | 单文件函数数受控；定位快 | 需要遵守命名约定（`testXxx` 不被 `go test` 直接发现） |
| 真实 SQLite / 真实子进程 | 测的是真实行为，而非 mock 的行为 | 单测略慢（每个用例建一次临时库）；子进程用例需要 fixture 基础设施 |
| 同域文件合并 | 文件名即索引，查找成本低 | 单文件行数较大（如 `recovery_test.go` 覆盖检查点 + 暂停恢复） |
