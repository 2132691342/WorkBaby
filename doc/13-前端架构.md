# 13 · 前端架构

技术栈：Vue 3（`<script setup>` + TS strict）+ Vite 6 + Pinia + Element Plus + Tailwind 4（叠加自研 `wb-ui.css` 玻璃拟态设计令牌）+ vue-router（hash 路由）。

源码在 `frontend/src/src`，`frontend/src/wailsjs` 是 Wails 生成的绑定。

## 目录

| 目录 | 职责 |
|---|---|
| `api/` | `http.ts`（基址与请求）、`client.ts`（路径白名单）、`stream.ts`（SSE）、`bootstrap.ts`（端口与契约引导）、`wails.ts` / `shellBridge.ts`（壳能力） |
| `stores/` | 18 个 Pinia store（含 `chat/` 子目录与 17 个 .ts），每域一个；`chat/` 下是流式解码与批处理 |
| `components/` | 24 个子目录，按域划分（chat / settings / tasks / skills / mcp …） |
| `chat/` | 纯模型层：消息块解析、对账合并、命令参数、流式块 |
| `composables/` | 主题、提示、对话框、快捷键、命令面板、节流渲染 |
| `i18n/` | zh / en 两份扁平字典 + `t()`（支持 `{0}` 插值） |
| `types/` | `api.ts` 全部后端契约类型 |
| `utils/` | 错误文本、时间格式化 |

## 启动引导

```
main.ts  创建应用（Pinia + router + ElementPlus），挂载前初始化主题
App.vue  ① initI18n ② bootstrapServer（拿端口）③ 注册桌宠/打开文件事件
         ④ 加载设置与会话 ⑤ 注册全局快捷键
         渲染四态：booting / bootError / pet 直出 / ready 外壳
```

`bootstrapServer` 通过 Wails 的 `GetServerPort` 与 `app:ready` 事件竞速拿端口，写入 localStorage，再 `initApi(port)`，最后校验契约版本（与后端 `ContractVersion` 不一致直接报错）。

## API 层

- `apiGet / apiPost`：`code===0` 返回 `data`，否则抛带 `code` 的错误
- `client.ts` 的 `KNOWN_PREFIXES` 做路径白名单校验——前端调了后端没接线的路径会立刻抛错，而不是静默 404（由 `check-contract.ps1` 保证与后端路由前缀同步）
- `stream.ts`：`streamChat()` 先 POST 拿 `run_id`，再开 `EventSource(/events?scope=chat&runId=…)`，内置重放、双看门狗、退避重连，并把 20+ 个 SSE 事件归一为 `ChatStreamEvent`

## Store 清单

| Store | 职责 |
|---|---|
| `chat` | 主链路：会话 CRUD、消息加载与对账、发送/中断/续跑、审批闭环、目标模式、待办、文件变更、上下文占用 |
| `sideChat` | 辅助对话（主链路的精简镜像） |

| `trust` | 目录信任决策 |
| `files` `folders` | 受管文件与文件夹树 |
| `pet` `docs` `dashboard` `admin` `home` | 桌宠、内置文档、仪表盘、系统概览、首页 |

## 聊天页

`ChatView.vue`：头部（标题重命名、运行态、模型、工作区、停止、上下文环、右栏 tab、更多菜单）→ 目标卡 / 消息列表 / 计划钉住 / 输入框 | 右栏（工作区 / 变更 / 任务 / 辅助对话，各带徽标，点已激活即收起）。

`ChatInput.vue` 的输入能力：

- **斜杠命令**：`/` 唤起面板（完整列表见应用内 `/help` 或后端 `BuiltinCommands`）。内置含 `/new /clear /compact /model /agent /trust /tasks /export /help` 等；自定义命令带模板会在发送时展开参数
- **@ 引用**：技能 + 工作区真实文件树（按扩展名与体积推断目录），上限 24
- **附件**：对话框选择，也支持粘贴与拖拽
- **权限模式**：四档切换，`full` 显式提示风险
- **轮中排队**：run 进行中输入的内容进队列，轮间注入

## 消息渲染与对账

`MessageList` → `MessageItem` → `MessageBlocksRenderer`。块模型在 `chat/models/blocks.ts`：持久化块直接解析，无块时从 `tool_calls_json` 降级重建；`groupToolRuns` 把相邻的连续工具调用合并成一组（不重排、不丢块）。

流式对账在 `chat/models/merge.ts`：

- `contentKey = role|前120字` 用于本地乐观行与权威行的配对
- `resolveRunAssistant` 返回 `dedupe`（权威已有，不重复追加）/ `fill`（权威是空占位，原地填）/ `missing`（后端未落库，补一条）
- `mergeLoadedMessages` 处理重影、重复堆叠、已删消息残留、断线丢增量四类事故

## 设置与首启引导

设置页 4 个主 tab（模型 / 能力 / 数据 / 系统）共 18 个 section，`?tab=` 为真相源（旧路由重定向过来），section 组件按需异步加载。

首启引导：无任何 Provider 时，模型页展示预设卡（点一下预填表单），可跳过或手动新建；消息列表空态也给直达设置页的入口。

## 样式与国际化

- `wb-ui.css` 提供玻璃拟态设计令牌（表面、描边、强调、状态色）与 `.btn/.badge/.input` 等基础类；`themes.css` 管主题与背景
- i18n 为扁平 key（`域.键`），zh / en 两份字典**键集合与顺序必须一致**，由 `scripts/i18n-sync.mjs check` 校验（当前 1627 键）

## 工程化

- `npm run typecheck`（`vue-tsc --noEmit`）、`npm run test`（vitest，jsdom）、`npm run build`（`vue-tsc -b && vite build`，产物 `dist` 供 `go:embed`）
- `unplugin-vue-components` 自动生成 `components.d.ts`（模板免 import 组件）、`unplugin-auto-import` 生成 `auto-import.d.ts`
- 测试只有 2 个文件：`chat/__tests__/messageView.spec.ts`（消息对账 / 块分组 / 命令参数）、`chat/__tests__/streamPipeline.spec.ts`（流事件管线）
