# 13 · 前端架构

Vue 3 + TypeScript + Vite，Wails v2 内嵌（hash 路由、无服务端 history 回退）。
业务数据全部经 HTTP `/api/v1`，系统能力（对话框/剪贴板/窗口）经 Wails 绑定。

## 目录

```
src/src/
├── api/          http（统一 unwrap）/ client（路径白名单）/ stream（SSE）/ bootstrap（端口注入）/ contract
├── chat/         纯领域模型：blocks（块序列）/ streamingBlocks / toolTrace / merge（消息对账）/ tokens
├── components/   chat（27）/ settings / dashboard / pet / common（EmptyState/Skeleton/PageState）
├── composables/  useTheme / useThrottledContent / useToast / useDialog / useShortcuts …
├── stores/       域 store（chat / sideChat / settings / pet / tasks / skills …）
├── types/api.ts  后端契约类型（与 RESP 字段一一对应）
├── markdown/     markdown-it 双实例 + DOMPurify + hljs/mermaid/katex
├── i18n/         中英词条（dict-zh / dict-en），key 对齐
└── style.css / themes.css / wb-ui.css   设计令牌与组件基元
```

## API 层

- `apiGet / apiPost`：`code===0` 返回 `data`，否则抛带 `code` 的错误（前端按 code 分流提示）
- `client.ts` 的 `KNOWN_PREFIXES` 做路径白名单校验——前端调了后端没接线的路径会立刻抛错而不是静默 404
  （由 `check-contract.ps1` 保证与后端路由前缀同步）
- `stream.ts`：`streamChat()` 先 POST 拿 `run_id`，再开 `EventSource(/events?scope=chat&session_id=…&run_id=…)`，
  内置重放、双看门狗（全静默 75s / 仅心跳 5min）、指数退避重连，并把 20+ 个 SSE 事件归一为 `ChatStreamEvent`；
  回调携带 `StreamEventMeta`（事件归属），store 据此丢弃非当前会话的事件

## 流式状态与会话隔离

流式状态是单份的（`streaming` / `streamingBlocks` / `activeHandle`），用 `streamingSessionID` 标记归属：

- **渲染**：`ChatView` 的 `streaming` 是 computed = `chat.streaming && streamingSessionID === currentID`——
  切走后后台 run 的增量不写视图
- **操作**：`cancelStream()` 用 `streamingSessionID`（而非 `currentID`）定位要停的 run；steer 只在「本会话正在跑」时可用
- **收尾**：`finally` 清空流式状态前先比对归属，避免把新会话的进行中气泡一起抹掉
- **事件入口**：非当前会话的事件直接丢弃，切回该会话或 run 结束后由权威快照补齐
- **连接**：`streamHandles` 按会话持有；`chat:done` 后连接保持（目标续跑无缝），同会话重发时替换旧连接

## 消息对账

`chat:done` 后前端拉权威快照，`merge.ts` 的 `resolveRunAssistant` 判定本条回复的落位：

- `dedupe`：权威已含 → 绝不本地再 push（避免同一回复两条）
- `fill`：权威是空占位 → 补正文 + 用本地块还原过程
- `missing`：权威未含 → 本地兜底插入

并发拉取用 `loadSeq` 守卫：过期响应直接丢弃（防止慢响应把新快照覆盖回旧快照）。

## 设计令牌

| 维度 | 约定 |
|---|---|
| 色值 | 只在 `themes.css` 定义（`--wb-*` + `[data-theme='light'|'dark']`）；`useTheme.ts` 的 THEMES 是预览视图，取值必须同步 |
| 组件用色 | 一律 Tailwind 的 `wb-*` token 类（`text-wb-ink` / `bg-wb-surface-2` / `border-wb-border`），不用 `gray-*` 等默认调色板（暗色会漏白） |
| 控件高度 | `--wb-ctl-h-sm`(24) / `--wb-ctl-h`(32) / `--wb-ctl-h-lg`(38) + `--wb-ctl-icon`(30)；禁止裸像素高度 |
| 字号 | `text-2xs`(10) / `text-xs2`(11) / `text-ctl`(12.5) + Tailwind 内置 xs/sm/base；禁止 `text-[Npx]` |
| 玻璃高光 | `--wb-surface-sheen`（唯一定义处） |
| 空态与骨架 | 统一 `EmptyState` / `Skeleton`，列表页经 `PageState` 三态包装；禁止 `el-empty` / `el-skeleton`（会拖入整套 EP 依赖） |
| 用户背景主色 | 经 `applyExtractedPrimary()` 统一应用/移除，别处不得直接设 `--wb-primary` |

## 交互约定

- **i18n**：所有面向用户文案走 `t()`；词条 key 中英对齐（含窗口按钮、导出模板、帮助正文）
- **契约**：字段一律 snake_case，与后端 RESP 完全一致（`types/api.ts` 是唯一类型来源）
- **流式渲染**：`StreamEventBatcher` 按帧批量落地（增量按到达顺序进 `streamingBlocks`，单一真相源），
  `chat:done` 等终态先 flush 再收尾
- **消息加载**：切会话先清空列表 + 显示骨架（`loadingMessages`），避免闪「空会话 + 示例卡」的假空态

## 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 业务全走 HTTP（不在 Wails 绑定里做业务） | 浏览器可直接调试、curl 可复现、SSE 可重放 | 需要端口注入（`app:ready`）与契约校验脚本 |
| 单份流式状态 + 会话归属标记 | 实现简单、渲染路径唯一 | 同一时刻只能"聚焦"一个会话的实时流（其他会话切回后靠快照补齐） |
| 自研设计令牌与组件基元 | 视觉一致可控；不把 EP 全量依赖拖进懒加载 chunk | 需要自己维护令牌与基元（EP 仅作补充） |
| 消息对账放在前端 | 断线/并发下不产生重复气泡 | 需要严格的三态判定与拉取序号守卫 |
| hash 路由 | Wails 本地资源无 history 回退问题 | URL 形态不如 history 模式美观（桌面端无感） |
