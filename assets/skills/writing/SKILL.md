# 写作与润色

动笔前先明确三件事：**给谁看**、**要对方看完做什么**、**多长合适**。用户没说的就问一句，别默认成「写给所有人看的万能文」。

## 通用套路

- 结论先行：第一段就说清结论或请求，背景放后面；对方只读第一段也能明白。
- 一段一个意思；能用列表不用长段；数字具体化，不用「大幅、显著」这类形容词硬撑。

## 各类型骨架

| 类型 | 骨架 |
|---|---|
| 周报 / 日报 | 本周进展（量化）· 风险与求助 · 下周计划，三节 |
| 邮件 | 第一句讲目的 → 一行背景 → 行动项清单（谁、什么时候、交付什么）→ 一句收尾 |
| 通知 / 公告 | 什么事 → 谁受影响 → 什么时间起 → 要做什么 |
| 申请 | 诉求一句话 → 理由两三条 → 承诺的补偿或替代方案 |
| 工作总结 | 目标回顾 → 做成的事（结果量化）→ 没做成的与原因 → 下一步 |

## 润色模式

用户给现稿要润色时：

1. 保留全部事实与数字，只动表达；删空话套话，不改结论。
2. 长 > 短：砍掉重复与铺垫，保持原意完整。
3. 交付时在文末用三五句话说明主要改动点，方便用户核对。

## 去 AI 味

- 删掉排比堆砌、空洞总结句（「综上所述」「在当今快速发展的时代」）。
- 形容词换数字：把「效果显著提升」换成「转化率从 3% 到 5%」这样的具体事实（没有数字就留占位符让用户补）。
- 口吻跟着读者走：对上简练恭敬，对客户新人友好，禁止公文腔乱串场。

## 硬性约束

- 用户没提供的数字、人名、日期用 `[占位符]` 标出，绝不编造。
- 交付正文用工作区文件（用户要求贴对话里才贴对话），文件名能看懂是哪篇。
- 写完回读一遍：检查有没有漏掉用户点名的要点。
