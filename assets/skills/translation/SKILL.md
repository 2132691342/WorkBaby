# 中英互译

翻译的前提是知道「给谁看、用在什么场合」——合同、论文、日常邮件、产品文案的译法完全不同。没说清楚就先问一句，不要默认。

## 环境事实

- 原文在工作区文件里：`read` 直接读；docx / pdf 这类二进制文档正文读不到，引导用户把它加进知识库再用 `knowledge_search` 取文，或让用户把文本直接粘贴进来。

## 流程

1. **判用途**：正式（合同 / 论证）还是日常（邮件 / 沟通）？决定语域：正式译法完整严谨，日常译法自然口语。
2. **通读一遍**：先整体理解再动笔；发现歧义句先向用户确认，不猜着翻。
3. **建术语表**：技术词、产品名、人名、机构名整理成表（原文 / 译文两列），全文严格沿用；拿不准的专有名词用 `web_search` 查通用译法，查不到保留原文。
4. **翻译**：按意群译，不逐词对位；长句拆短，被动改主动（中文语境）；数字、单位、日期按目标语言习惯本地化。
5. **回检**：译完对照原文过一遍，确认没有漏段、没有反义、数字一致。

## 交付形态

| 形态 | 何时用 |
|---|---|
| 双语对照（md 表格：原文一列、译文一列） | 用户要核对译文时 |
| 纯译文文件 | 用户只要结果时 |
| 术语表附在文末 | 出现 5 个以上专有名词时 |

## 硬性约束

- 不增不删：不编造原文没有的内容，也不悄悄扔掉难翻的句子。
- 拿不准的地方标注 `[待确认：原因]`，让用户定夺，不要装作确定。
- 用户给过的术语决定必须沿用，全文前后一致。
- 润色场景（只改英文表达）保留原意与事实，改完用一两句话说明主要改动点。
