# 深度调研

调研不是把搜到的东西堆在一起，而是带着问题找证据。整条链路分四步，每步的产物都落在工作区文件里，方便用户随时查看与补充。

## 环境事实

- `web_search` 找线索，`web_fetch` 读原文；搜索摘要只是索引，结论必须落到原文。
- 报告写工作区 markdown 文件；长报告先建目录（如 `research/`），逐项素材与最终报告分开存。

## 流程

1. **定问题**：把用户的模糊需求改写成一句可回答的问题，并列出 3-5 个必须回答的子问题。有歧义先问，不要自己猜方向。
2. **先给大纲**：把子问题扩成报告大纲（结论区 / 逐项分析 / 风险与盲区），给用户确认后再动身搜索。
3. **逐项搜集**：每个子问题独立搜 2-3 轮，关键词换着来（中英都试）；素材随手记进 `research/notes-*.md`，每条带来源 URL。
4. **交叉验证**：关键数字与结论至少两个独立来源印证；只有单一来源的，在报告里明确标注「单一来源，待核实」。
5. **成稿**：写 `research/report.md`，结论前置，正文按大纲走，文末列全部引用链接。

## 报告写法

| 部分 | 要求 |
|---|---|
| 结论 | 3 条以内，每条一句话，直接回答用户的问题 |
| 正文 | 按大纲逐项展开；数字必须有出处，观点标注是事实还是推断 |
| 对比表 | 选型 / 竞品类调研用表格收敛：维度做行、对象做列 |
| 盲区 | 明确写出没查到什么、什么信息可能过时 |

## 硬性约束

- 不编造：搜不到就写「未找到公开资料」，不许用想象补数字。
- 数字必须带来源与日期；价格、版本、政策类信息标明查询时间——它们很快会过时。
- 同一个关键词搜不到就换词（同义词、英文、更宽 / 更窄的表述），不原地重复同一条搜索超过两次。
- 报告里引用的事实都能回溯到 notes 文件里的某条素材。
