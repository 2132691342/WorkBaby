# 提示词打磨

一条好提示词让 AI 一次就做对；差提示词全靠来回追问。打磨的目标是「少轮次、可复用」。

## 四件套

| 件 | 写什么 | 反例 |
|---|---|---|
| 角色 | 这是什么身份、为谁服务 | （缺失：AI 自己猜视角） |
| 任务 | 一句话说清要做什么；多件事拆步骤编号 | 「帮我弄一下这个」 |
| 约束 | 不能做什么、必须遵守什么（字数 / 语言 / 事实来源） | （缺失：产出跑偏后反复返工） |
| 输出格式 | 交付形态：表格、代码块、分节标题，给一个示例最好 | （缺失：每次格式都不一样） |

## 常见病与治法

- **太笼统** → 加判断标准：「写得吸引人」改成「开头一句话让买家想点进详情页」。
- **一次塞太多任务** → 拆成编号步骤或拆成多次调用；上下文塞满反而每件都做不好。
- **没有成功标准** → 写清「什么样算好」，最好给 1-2 个好例子（few-shot）。
- **忘了说受众** → 明确读的人是谁，口吻深度全跟着变。

## 打磨循环

1. 按四件套重写提示词。
2. 用一条真实输入做小样测试，看输出差在哪。
3. 每次只改一处（加约束 / 调格式 / 换例子），再测一次；改动点太多就说不清哪处起了作用。
4. 定稿后交付「可直接复制」的提示词块，每处关键改动配一句话理由。

## 硬性约束

- 不替用户编造业务事实；提示词里的背景信息缺失时用 `[占位符]` 让用户补。
- 交付必须给「可直接复制」的完整提示词块，不要只给「改进思路」。
- 中英提示词都写时明确标注哪个是主版本。
