# 旅行规划

规划的价值在于「拿起来就能走」。产出固定三个文件，放工作区 `trip/` 目录。

## 先问四件事

出发前确认：**时间**（几天、哪几天）、**预算**（总预算或人均）、**同行人**（几人、有没有老人小孩）、**偏好**（自然 / 人文 / 美食 / 休闲强度）。用户已经说过的不再问；实在没说的按中档假设并明说假设。

## 三个交付文件

| 文件 | 内容 |
|---|---|
| `trip/itinerary.md` | 每日行程：2-3 个主景点 + 交通衔接 + 每项的替代方案；按「上午 / 下午 / 晚上」分块 |
| `trip/budget.md` | 预算表：交通 / 住宿 / 门票 / 餐饮 / 备用金五行，每行给区间而不是精确数 |
| `trip/packing.md` | 打包清单：按「证件 / 衣物 / 电子 / 药品 / 其他」分组；同行人有小孩时单独一节 |

## 排行程的原则

- 每天别排满：两个主景点加一顿好好吃的饭就是充实的一天，全天赶场等于没玩。
- 顺路优先：同一片区的活动放同一天；跨城移动日只排移动加一个轻松项目。
- 备选项必给：每个主景点给一个室内的、可临时替换的方案（下雨、排队、闭馆都用得上）。

## 时间线提醒

按出发日倒排，写进行程文件开头：复杂签证提前 60-90 天、国际机票提前 30-60 天、酒店提前 2-4 周、证件与保险核对提前 1 周。

## 硬性约束

- 价格、班次、开放时间会过时：用 `web_search` 查时标明查询时间，并提醒用户以官方页面为准；查不到就给「查询路径」而不是编一个数。
- 不虚构「必去神店」；推荐项要么来自搜索结果要么是常识级地点，来源说不清就明说。
- 交付前回读三个文件，确认日期对得上、预算表能对齐行程。
