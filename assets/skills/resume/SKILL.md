# 简历定制

简历的每一行都必须能在用户真实经历里找到出处。定制是重新组织与表达，不是注水。

## 铁律

- 不编造：数字、项目、技术栈、职级一律不凭空补；用户素材里没有的就留占位符 `[请补充：具体数值]`。
- 原文件只读：用户上传的简历永不被修改，所有产出写进工作区 `resume-output/` 下的新文件。
- 联系方式缺失用占位符（`[电话待填写]`），绝不生成假的号码邮箱。

## 流程

1. **收素材**：向用户要两样东西——现有简历（master）与目标岗位 JD。只有 JD 没有 master 就先逐项问经历。
2. **拆 JD**：把岗位要求拆成三类关键词：硬技能、业务经验、软性要求，列成清单。
3. **对齐**：master 里的每段经历改写成动词开头 + 做了什么 + 量化结果；结果数字缺失就问用户，问不到留占位符。
4. **排布**：与 JD 强相关的经历放前、写满；无关的压缩成一行。教育背景按用户所处阶段（应届在前 / 社招在后）。
5. **交付**：写 `resume-output/resume-{公司或岗位}.md`；需要投递时说明可在 Word 里排版另存 PDF。

## 打分模式

用户问「这份简历对这个岗位能打几分」时：

| 输出 | 内容 |
|---|---|
| 覆盖率 | JD 关键词清单逐项标注「已覆盖 / 未覆盖」，给百分比 |
| 差距清单 | 未覆盖项按「能靠现有经历补」与「确实缺失」分两组 |
| 修改建议 | 每条差距给出可直接替换的改写句 |

## 硬性约束

- docx / pdf 简历正文直接读不到：引导用户加进知识库走 `knowledge_search`，或让用户粘贴文本。
- 英文简历是按英文习惯重写，不是逐句翻译；用户没有给过的英文表述不要硬造。
- 一次失败换方法，不原地重复同一条操作；交付前回读产物确认格式完整。
