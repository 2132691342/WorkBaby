# 创建 WorkBaby 技能

技能是一段**按需注入**的方法论：平时只在系统提示里占一行清单，模型需要时才 `read` 它的正文照着做。文件即真相源（不落数据库）。

## 先判断是否值得建技能

| 判断 | 结论 |
|---|---|
| 一次性任务 | 不建，直接对话 |
| 反复出现、每次都要交代同样规矩 | 建 |
| 通用能力（写作 / 翻译 / 分析） | 不建，模型本来就会 |

## SKILL.md 格式

```markdown
---
name: my-skill
when_to_use:
  - 触发词一
  - trigger-word
description: 一句话说明这个技能做什么、什么时候用。
---

# 正文标题

正文：分步骤的操作规程。
```

| 字段 | 规则 |
|---|---|
| `name` | 必填；小写字母、数字、连字符，≤64 字符，与目录名一致（中文名不合法） |
| `description` | 必填；**决定会不会被用到**，写清「做什么 + 何时用」，不写实现方式 |
| `when_to_use` | 触发词列表（或单个字符串）；会原样列进模型的技能清单，写用户真实会说的中文词与英文词 |

其余字段（version、allowed_tools 等）**当前不会被读取**，写了没有任何作用，别依赖。

## 正文怎么写才管用

1. 写成**可判定的动作**，不要写「要认真、要专业」这类无法验证的话。
2. 用表格做「场景 → 做法」的快速索引，模型先查表再行动。
3. 只引用**真实存在的工具**（read / write / edit / ls / find / grep / powershell / python / web_search / web_fetch / knowledge_search），写错工具名会让整段流程第一步就失败。
4. 写清验收：做完后用什么命令、读什么文件来证明做完了。
5. 写清失败路径：某步失败后改用什么办法，而不是原样重试。
6. 正文自包含：只会加载 SKILL.md 这一个文件，**不要引用 `references/*.md` 或 `scripts/*.py`，它们不会被加载**。

## 落地位置

| 来源 | 位置 | 说明 |
|---|---|---|
| 内置（随程序发布） | `assets/skills/{name}/SKILL.md` | 对用户只读，改代码后重启生效 |
| 自定义 | `%APPDATA%\WorkBaby\skills\{name}\SKILL.md` | 用户自己的技能（可用环境变量 `WORKBABY_HOME` 改根目录） |
| 工作区 | `<工作区>/.workbaby/skills/{name}\SKILL.md` | 只对该工作区的会话可见，同名覆盖全局 |

新建后校验：

1. `name` 与目录名一致，且不与已有技能重名。
2. 用一句真实用户话去试：模型看到清单里的 description + 触发词，会不会想到它。
3. 走一遍正文流程，确认每一步引用的工具都真实存在（见上表）。
4. 内置技能不能改；要迭代先放到自定义目录，验证好了再迁回内置。
