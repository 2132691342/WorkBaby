# 用量与花费

仪表盘上的每个数字都来自 PI 的会话文件：每条助手消息里都带着上游报的用量，WorkBaby 只是把它们加起来。

## 读数含义

| 读数 | 含义 |
|---|---|
| 总 token | 区间内所有模型调用的 token 之和 |
| 输入 / 输出 | 你发出去的量 / 助手回来的量 |
| 缓存命中率 | 命中的提示词 token ÷ 提示词总量。上游把提示词拆成「命中 / 未命中 / 新写入」三段报，三者相加才是分母。长对话里这一项决定成本是线性涨还是几乎不涨 |
| 估算花费 | 按 `models.json` 里模型的单价折算（美元）。单价没填就显示 0；它是趋势读数，不是账单 |

## 按天、按模型、按会话

- **趋势图**：每天输入与输出两条线。没有用量的日子画 0，不跳过——缺一天看不出趋势的形状。
- **按模型**：谁占了大头。同一个模型被多个服务商提供时，按「服务商 + 模型」分开算。
- **用量最高的会话**：点一下直接跳进那段对话。

## 为什么和我账单上的数字不完全一样

- 上游对缓存、推理 token 的计费口径各不相同；
- `models.json` 里的单价是静态的，促销价、阶梯价都不在里面；
- 中断、失败的重试可能已经计费但没落进会话文件。

所以这里的数字用于「看趋势、找异常」，不用于对账。

## 想省一点

| 做法 | 效果 |
|---|---|
| 换便宜模型 | 输入输出单价直接决定花费 |
| 减少思考档 | 推理 token 常常是账单里的意外项 |
| 及时开新对话 | 上下文越长，每次请求的输入越大 |
| 让它压缩 | 上下文快满时 PI 会整理较早内容，压完的下一轮输入会明显变小 |
