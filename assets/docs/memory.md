# 记忆中心

WorkBaby 的长期记忆是一份**人能直接编辑的 Markdown 文件**（`MEMORY.md`），检索索引只是它的派生物——数据可迁移、可手工修正，索引丢了重建即可。

## 1. 记忆长什么样

文件按四个固定分节组织：

```markdown
# 长期记忆

## 用户偏好
- 回复用中文

## 事实
- 项目用 Go 1.24

## 流程
- 提交前跑 go test ./...

## 项目约定
- 错误码按段位分配
```

| 约束 | 值 |
|---|---|
| 固定分节 | 用户偏好 / 事实 / 流程 / 项目约定（未知分节自动归入「事实」） |
| 条目上限 | 200 条（写满自动丢最旧一条） |
| 单条长度 | 400 字符 |
| 重复条目 | 自动去重 |

## 2. 怎么写

| 路径 | 说明 |
|---|---|
| 模型主动写 | 对话中说「记住：……」，模型会用 `memory_write` 工具追加 |
| 设置页手动写 | 「设置 → 记忆中心」增删条目或整篇覆盖 |

WorkBaby **不做自动沉淀**：对话结束后不会偷偷总结写入。要记什么，由你或模型明说——这样记忆里没有噪声，也随时可以修正。

## 3. 怎么用

- 每轮对话前，系统按你的输入自动检索记忆（最多召回 6 条）注入上下文
- 「设置 → 记忆中心」提供检索框与条目列表，可直接查看 / 修改记忆内容
- 记忆开关在「设置 → 记忆中心」：关闭后既不注入，也不再暴露 `memory_write` 工具

## 4. 记忆存在哪

| 场景 | 位置 |
|---|---|
| 普通会话 | 数据根 `memory/{会话ID}/MEMORY.md` |
| 绑定了工作区的会话 | 工作区内 `.workbaby/memory/{会话ID}/MEMORY.md`（过程数据跟着工作区走） |

## 5. 记忆 vs 知识库

| | 记忆 | 知识库 |
|---|---|---|
| 内容 | 简短、稳定的事实（关于你和你的项目） | 长文档 |
| 写入 | 逐条追加 | 文档级导入 |
| 归属 | 单个会话 | 全局 |

一句话：**「我是谁、项目怎么运作」放记忆；「资料原文」放知识库。**
