# 子智能体与任务委派

遇到大而杂的任务时，主对话可以把一块工作**委派**给一个独立的子 Agent：它在隔离环境里跑完，只把摘要交回来。

## 1. 委派（delegate_task）

模型在对话中调用 `delegate_task` 工具即可委派，四重隔离保证父对话不被污染：

| 隔离维度 | 实现 |
|---|---|
| 上下文 | 子任务只装人设 + 任务描述，不带父对话历史 |
| 预算 | 独立的轮次、工具超时与墙钟上限 |
| 工具 | 只能用「父对话已暴露 ∩ 子智能体策略」的工具，只能收缩不能升权 |
| 正文 | 只回传摘要；正文与思考不进父回答，事件单独打标签 |

聊天页会以「子 Agent 生命周期」块显示委派的开始与结束。相同的委派目标（同名 + 同任务）并发时共享一次执行。

## 2. 自定义子智能体

「设置 → 子智能体」可以定义自己的 Agent 档案：

| 字段 | 说明 |
|---|---|
| 名称 | kebab-case 小写（如 `code-reviewer`），全局唯一 |
| 人设 | 系统提示词，决定它「是谁、怎么干活」 |
| 工具策略 | 允许使用的工具范围（委派时只会在此之上收缩） |
| 预算 | 最大轮数 / 超时等上限 |
| 模型 | 可指定与主对话不同的模型 |

- **启停**：停用后立即从注册表摘除，委派与会话切换都不可再选
- **文件方式**：把定义文件放进数据根 `agents/*.md`（与界面同构）；同名时以界面为准

## 3. 会话级切换

除了委派，也可以把整个会话切换到某个子智能体上运行：会话「Agent」下拉（或设置接口）选择后，本会话后续对话都用它的人设与工具策略。

## 4. 什么时候用

| 场景 | 建议 |
|---|---|
| 大范围检索 / 阅读后再总结 | 委派给子任务，父对话只收摘要，省上下文 |
| 代码审查、批量重命名等机械工作 | 定义专门的子智能体（人设 + 工具白名单） |
| 需要换模型跑特定任务 | 子智能体指定不同模型 |
