# 配置模型服务

WorkBaby 自己不生产智能，它把你说的话转给一家「模型服务」去回答。
这一步只需要做一次。

## 怎么配

1. **设置 → 模型服务 → 新增服务商**
2. 选一个模板（常见服务商都在列表里），接口地址会自动填好
3. 把 API Key 粘贴进去（在服务商官网后台申请，形如 `sk-...`）
4. 点 **拉取模型列表**，从结果里勾一个模型（推荐带「对话 / Chat」字样的）
5. **保存**，然后点 **测试** —— 显示「连接正常」就配好了
6. 点模型行上的 **设为默认**，之后新对话都用它

## 模型参数与能力（默认不用动）

「模型参数与能力」展开后，每个模型一行，七项可设。程序内置了一份常见模型的
资料表，认得出的模型会自动填好，**不展开就一切照默认走**。只有这几种情况才需要动：

| 要设什么 | 什么时候设 |
|---|---|
| 上下文窗口 | 私有部署或改了名字的模型，资料表认不出（界面会标「未识别」） |
| 最大输出 | 一次回答太长被截断，或者服务商对输出另有更小的上限 |
| 推理 | 资料表没收录这个模型是不是推理型，而你知道它是 |
| 识图 / 工具调用 | 这个模型不支持却按支持对待了（发图报错、或总不见它调工具） |
| 温度 / Top P | 想让输出更稳（调低）或更发散（调高）；留空 = 用该模型自己的默认 |

几处容易踩的规则，说清楚省得试：

- **留空和填 0 不是一回事**：留空 = 跟随默认；温度填 0 = 刻意要它每次都一样
- **最大输出留空**是按窗口算出来的（窗口的八分之一，且不超过厂商上限）；填了就直接用你填的
- **推理这一格只能打开不能关掉**：资料表认定它是推理型时，那是事实不是猜测
- 改完点这一行的 **保存**，立刻生效，不用重启

## 该选哪个模型

| 场景 | 建议 |
|---|---|
| 日常办公（写东西、读文件） | 主力对话模型，便宜够用即可 |
| 复杂任务（多步骤、写代码） | 能力更强的大模型 |
| 长文档摘要 | 挑上下文窗口大（128K 以上）的模型 |

不用纠结：先配一个能用的，用起来再说。之后随时可以加第二个、第三个。

## 换模型

- **全局**：设置 → 模型服务 → 把另一个设为默认
- **单个对话**：对话页底部输入框左边的模型按钮，只改这个对话

## 和命令行共用一份配置

界面里配的服务商与密钥，写进的是助手引擎自己读的那个配置文件
（`models.json`，在本机数据目录的 `pi-agent` 下）。所以：

- 你在界面里配好的，在命令行里敲 `pi` 也一样能用
- 反过来，如果你以前在命令行里配过，第一次打开界面会把它读进来，不会丢
- 界面上改过之后，以界面为准；同时在两边改同一项没有意义，改一处就够

密钥在界面里加密保存，写进配置文件时是明文——这是助手引擎要求的格式。
不想在界面上留密钥，可以只在命令行里配，界面会读但不会显示出来。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 测试报「401 / 未授权」 | Key 填错或过期，回服务商后台重新复制 |
| 测试报「连接失败」 | 接口地址填错，或网络不通（公司网络可能限制访问） |
| 拉不到模型列表 | 有些服务商不支持列表接口，直接在输入框手填模型名即可 |
| 回答很慢 | 换一个更小的模型，或检查网络 |
