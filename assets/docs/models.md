# 模型服务

WorkBaby 的「设置 · 模型服务」读写的就是 PI 的 `models.json`。
你在别处（命令行、手工编辑、别的配置工具）加的服务商，这里打开就能看到；这里加的服务商，`pi` 命令也立刻能用。

## 一条服务商是什么

| 字段 | 说明 |
|---|---|
| 显示名 | 只影响界面；服务商的键会从它自动生成 |
| 接口类型 | 大多数中转网关与本地模型是「OpenAI 兼容」；官方 Anthropic / Google / Azure 各有自己的类型 |
| 接口地址 | 形如 `https://api.example.com/v1`（不带 `/models`） |
| API Key | 写进 `models.json` 的 `apiKey`，界面只显示掩码；点「显示」才看得到明文 |
| 模型 | 这个服务下你打算用的模型清单：模型 id、显示名、上下文窗口、输出上限、是否识图、是否思考 |

`models.json` 里保存的是明文密钥（PI 就是这么读的），所以那份文件的权限交给系统账号管理，别提交进 Git。

## 从上游拉模型

点「从上游拉取」会请求 `{接口地址}/models`，把返回的模型名列出来供你勾选。
拉不到也不影响使用——手动填模型名一样工作，只是少了自动补全。

## 设默认模型

「设默认」写的是 PI `settings.json` 里的 `defaultProvider` / `defaultModel`：

- 新对话默认用它；
- 命令行 `pi` 启动时也用它。

## 连通测试

「测试」会用第一个模型向上游要一次模型列表：

- 成功：连上了，并报出上游一共有多少个模型；
- 失败：把上游返回的状态码与前几百个字符带出来，据此判断是地址错、密钥错还是网络不通。

## 常见问题

**改了配置但助手还是用老模型？**
点保存后，WorkBaby 会重启当前空闲的 PI 进程。如果有对话正在跑，它会等那一轮结束再重启——所以最稳妥的是先停下正在跑的那一轮。

**只想让某一条对话换模型？**
不用改这里：直接在对话输入框下方点模型 chip。

**为什么模型有「识图 / 无思考」标签？**
这两个能力由 `models.json` 里模型的 `input` 与 `reasoning` 决定。标了「无思考」的模型即使把思考档调到「最多」也不会思考。
