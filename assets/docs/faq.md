# 常见问题

## 我明明装了很多技能 / 插件，为什么界面里没有？

先看「设置 · 行为」页底的**配置目录**。

WorkBaby 用的就是 `~/.pi/agent`（如果设了 `PI_CODING_AGENT_DIR` 环境变量，就用那个）。它与 `pi` 命令是同一份——所以只要 `pi` 能看到，界面就该能看到。

如果两边不一致：

1. 确认你启动 WorkBaby 时的环境变量与命令行一致；
2. 点一次「刷新」按钮（技能 / 插件 / 工具页都有）重扫磁盘；
3. 装包之后列表没跟上时，点「重载」重启一次 PI。

## 助手起不来 / 一直转圈

按顺序看「设置 · 行为」页底的三条环境信息：

| 卡在 | 原因 | 怎么办 |
|---|---|---|
| Node | 系统 Node 太旧且内置运行时解压失败 | 装一个 Node 22+，或看日志里的解压失败原因 |
| PI | 还没装 | 环境向导里点「安装」 |
| 模型 | 没配可用服务 | 设置 · 模型服务里加一个 |

日志在 `%APPDATA%\WorkBaby\logs\`。

## 同一个文件夹里为什么不能同时开两个对话？

PI 的进程模型是「一个工作目录一个进程」，进程的当前会话只有一个。
所以同一个目录里第二条对话要等第一条跑完——这是内核的约束，不是界面的限制。

不同目录可以并行，各自的进程互不影响。

## 停止之后助手还在写？

「停止」会先取回排队里的消息，再中止当前这一轮。落盘与收尾要走完，界面会随后收到一条「完成」信号。
如果你在停止后立刻又发了消息，它会作为新的一轮开始。

## 它会不会偷偷执行危险命令？

它跑命令不假——这是它「会干活」的部分。默认它不问你，这与 `pi` 命令行的行为一致。

想加一道闸门就装一个拦 `tool_call` 的扩展：问题会以卡片形式出现在对话末尾，你可以拒绝，拒绝永远安全。

## 「回到开头」为什么开了一条新对话？

PI 没有「把会话指针拨回去」的协议面，所以「从开头重来」最安全的做法是**分叉成一条新会话**，原对话完整保留。

## 导出成 HTML 有什么用？

导出的是一份自带样式的静态文件，双击就能看，不依赖 WorkBaby。适合归档一次重要的工作记录。
