# 技能与插件

技能与插件都归 PI 管：WorkBaby 只把它们列出来，并把开关翻译成 PI 自己的开关。

## 技能（改的是目录）

一个技能 = 一个目录 + 里面的 `SKILL.md`。PI 在启动时扫描这些位置：

| 位置 | 来源标记 | 谁能改 |
|---|---|---|
| `~/.pi/agent/skills/` | 我的技能 | 你（启用 / 停用 / 删除 / 导入） |
| `<项目>/.pi/skills/`、`<项目>/.agents/skills/` | 工作区 | 项目自己 |
| 插件包的 `skills/` | 插件包 | 随包安装与卸载 |

界面上的「停用」不是记一个开关，而是把目录移到 `~/.pi/agent/skills.disabled/`：
PI 只扫 `skills/`，所以停用的技能对模型真的不存在；想恢复时再移回来。
工作区与包里的技能是别人的文件，界面不搬，只给一句说明。

点技能名可以看正文。正文就是模型按需读取的内容——描述写得越具体，它越容易在正确的时机想起这个技能。

### 导入

「导入」选一个 `SKILL.md`：整个技能目录（含脚本与素材）会一起复制进 `~/.pi/agent/skills/`。

## 插件（扩展与包）

PI 有两套扩展机制，界面上分两块：

### 包（推荐）

`pi install npm:@scope/pkg`、`git:github.com/owner/repo`、`./本地目录` 三种来源。
一个包里可以同时带扩展、技能、提示模板、主题——装上就一起生效。

- 界面上「安装 / 卸载」调用的就是 PI 自己的 CLI，输出实时打印在面板里；
- 已声明的包列在 `settings.json` 的 `packages` 里，包目录落在 `~/.pi/agent/npm/node_modules/`；
- 登记了但目录不在的会标「目录缺失」，不会假装它还能用。

### 插件市场

插件页签里有「插件市场」：按 PI 官方的发现机制（npm 上带 `pi-package` 关键字的包）
列出生态里能装的包，写明它是干什么的、最新版本、谁发布的；装过的会标出来。
看中哪个点「安装」就走上面同一条安装链路。生态还小，找不到想要的就回「已安装」
页签用输入框直接装任意 npm 包。

### 扩展（单个文件）

`~/.pi/agent/extensions/` 下的 `.ts` / `.js` 文件或目录，登记在 `settings.json` 的 `extensions` 里。

- 「启用 / 停用」改的是登记表，文件不搬走；
- 「导入」把磁盘上的扩展复制进 extensions 目录并登记；
- 改完都会重启 PI：扩展是启动期加载的，不重启等于没改。

## 怎么选

| 你想做的事 | 用哪种 |
|---|---|
| 给助手加一套手法（写周报、审代码） | 技能 |
| 给助手加新工具 / 新命令 | 扩展或包 |
| 把一整套东西分发给同事 | 包 |
