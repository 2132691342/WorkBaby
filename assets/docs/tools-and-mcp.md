# 工具与 MCP

## 工具清单从哪来

「设置 · 工具」列的不是 WorkBaby 自己实现的功能，而是 **PI 那一刻真能调到的工具**：

- PI 每开一次对话，都会把工具声明写进会话文件（名字 + 说明）；
- 界面读最近一条会话的这份声明，所以看到的就是模型眼里的工具表；
- 还没有任何会话时，按 PI 的内置工具表推断，并明确标注「还没有会话快照」。

工具来自三处：

| 来源 | 例子 |
|---|---|
| 内置 | 读 / 写 / 改文件、跑命令、搜内容、找文件 |
| 插件 | 插件包里注册的工具（提问、检索……） |
| MCP | 外部服务提供的工具，名字形如 `mcp__<服务>__<工具>` |

## 启停

内置与插件工具的开关写的是 PI `settings.json` 的 `defaultTools`：

- 列表里只有普通名字 = 用这份名单**替换**默认集；
- 只有 `+name` / `-name` 条目 = 在默认集上**增减**。

这一页的开关写的是前者：一份明确的名单，不会因为 PI 以后新增一个工具就悄悄出现在你的界面上。
唯一的例外是命令执行环境的自愈：系统里找不到真 bash 时，它会往名单里追加
`+powershell` / `-bash` 把工具换成 PowerShell；之后找到 bash，只要名单没被你改过，就还原回去。

MCP 工具的可见范围由 `mcp.json` 里的暴露档（`exposure`）决定，不在这一页开关。

## MCP 服务

MCP 让助手用上外部工具：浏览器、数据库、内部系统。

- 配置在 `~/.pi/agent/mcp.json`（全局）与 `<项目>/.pi/mcp.json`（项目级）；
- 界面上的「已连接 / 连接失败 / 未探测」与工具清单来自 `pi mcp list --json`——连没连上只有 PI 知道；
- 配置是 JSON 原文编辑：保存前会做语法与 `mcpServers` 结构校验，不通过一个字符都不写；
- 需要 OAuth 的服务点「登录」，在浏览器里完成授权，再点「重连」。

一个最小例子：

```json
{
  "mcpServers": {
    "my-server": {
      "command": "node",
      "args": ["C:/path/to/server.js"]
    }
  }
}
```

远程服务用 `url` 代替 `command`：

```json
{
  "mcpServers": {
    "remote": { "type": "streamable-http", "url": "http://127.0.0.1:17321/mcp" }
  }
}
```

改完要么点「保存」（会重启 PI），要么点「重连」。

## 动手前会问你吗

PI 的默认行为是**不打断**：它能直接读写文件、跑命令。

需要确认时，装一个拦 `tool_call` 的扩展即可——它弹出来的问题会以卡片形式出现在对话末尾，你在界面上点「确认 / 拒绝」就是回答。

这类提问由引擎发起，WorkBaby 只负责显示与回传，不自己判断该不该问。
