# 12 · 用户手册（应用内帮助页）

## 定位

应用内只读手册：新手不离开窗口就能查「怎么配模型、怎么审批、数据在哪」。
内容随 exe 打包（离线可用），不依赖任何在线文档。

## 设计

| 层 | 实现 | 职责 |
|---|---|---|
| 内容 | `assets/docs/*.md`（`go:embed`） | 快速上手 / 配置模型服务 / 工具与安全 / 知识库与技能 / 常见问题 |
| 接口 | `GET /api/v1/docs` · `GET /api/v1/docs/:name` | 目录（首行 `# 标题` 即目录标题）+ 单篇 Markdown |
| 界面 | `views/HelpView.vue`（`/help/:name?`） | 左侧目录 + 右侧 `.prose` 渲染；入口在导航轨道「帮助」 |

## 契约

- `name` 只放行 `[a-z0-9-_]`（≤64 字符），越界与不存在统一报 1012——挡路径穿越不靠路由层
- `content` 是原始 Markdown：渲染（marked + DOMPurify）一律在前端，复用 `utils/md.ts`；
  渲染前剥掉正文首行 H1——页面头已经渲染过标题，正文再渲一遍就是两层同样的标题
- 目录顺序由 `docRank` 白名单决定：快速上手 → 配置模型服务 → 工具与安全 →
  知识库与技能 → 常见问题 → 其余按文件名——第一篇永远是最需要的

## 关键流程

1. 轨道「帮助」→ `/help` → 无文档名时 replace 到第一篇
2. 欢迎页「看教程」直达 `/help/models`：没配模型服务时的主路径

## 约束

- 只读：不可编辑、不可删除、不落库；改内容 = 改 `assets/docs/` 后重新构建
- 措辞与界面一致：按钮叫「放行 / 拒绝」，不叫「批准 / 驳回」

## 取舍

- **手册正文只存在于 `assets/docs/`（单一真相）**：specs 只讲实现，避免两处维护同一份话术；
  代价是本篇不能当手册直接读
- **排序白名单**：新增文档忘记登记会排在最后；换来「第一篇永远是最需要的」
