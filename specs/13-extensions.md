# 13 · 插件（扩展与包）

## 两套机制，不要混

| | 包（package） | 扩展（extension） |
|---|---|---|
| 形态 | 一个 npm / git / 本地目录 | 一个 `.ts` / `.js` 文件或目录 |
| 能力 | 扩展 + 技能 + 提示模板 + 主题，一次装齐 | 只有扩展 |
| 安装 | `pi install <source>` | 复制进 `extensions/` 并登记 |
| 记录在 | `settings.json` 的 `packages` | `settings.json` 的 `extensions` |
| 落地位置 | `~/.pi/agent/npm/node_modules/<name>` | `~/.pi/agent/extensions/<name>` |
| 界面动作 | 安装 / 卸载 / 看目录 | 启用 / 停用 / 导入 / 删除 |

## 包

```
来源写法：npm:@scope/pkg[@ver] · git:github.com/owner/repo[@ref] · ./本地目录 · https://…
```

- 装 / 卸都调 PI 自己的 CLI，WorkBaby 不重写一遍包的解析与版本规则；
- 输出按行回传（`chat:setup`）：npm 拉包可能几十秒，没有进度界面会被当成卡死；
- 同一时刻只允许一个装 / 卸动作（并发 npm 会写坏同一个目录）；
- 清单里的包若目录不在，界面标「目录缺失」——静默消失会让人以为设置没保存；
- 包自带的技能随包装卸，技能页把它们标为「插件包」且不可搬动。

## 扩展

- **登记表就是开关**：`settings.json` 的 `extensions` 里有它就是启用；
  文件不搬走——PI 只读登记表，搬目录会让「导入过的插件」在磁盘上反复挪位置。
- 支持通配条目（`!pattern` / `+path` / `builtin:*`）：界面把它们标为只读，
  不值得为几种 glob 语法写一个编辑器。
- 删除 = 删磁盘文件 + 摘登记项。

## 生效时机

扩展与包都是**启动期加载**的：

```
改登记表 → 写 settings.json → 重启全部 PI 进程
```

因此界面上每个改动都会触发一次重启。重启会中断正在跑的对话——这是「改了就有用」的代价，
比起「改了没反应」更容易解释。

## 与 PI 的分工

| 事 | 谁做 |
|---|---|
| 包的解析、安装、依赖、模块映射 | PI |
| 扩展的加载与执行 | PI |
| 列出条目、翻译开关、流式回传进度 | WorkBaby |

## 取舍

- **调 CLI 而不是自己 npm install**：PI 的包规则会演进（模块映射、peer 抑制、git reconcil）；
  跟着它走永远不会分叉，代价是装包依赖 PI 已就绪。
- **登记表启停**：可逆、可脚本化；代价是停用后文件还在磁盘上（这正是「还能再启用」的前提）。
- **一次一个装包动作**：安全；代价是用户要排队。
