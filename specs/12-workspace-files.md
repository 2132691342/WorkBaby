# 12 · 工作区文件面板

## 定位

助手在用户的文件夹里干活，而用户需要**自己看见那个文件夹**：确认它找得到文件、
知道一个相对路径到底指向哪里、把某个文件直接塞进对话。

这块回答三个问题：工作区里有什么、某一层里有哪些条目、`@` 引用时选的是哪个文件。
它**只读**：不看内容、不打开、不编辑。看差异去 [08](08-workspace-git.md)，
把文件读进对话走 [02](02-session.md) 的附件链路。

## 设计

| 决策 | 选择 | 为什么 | 代价 |
|---|---|---|---|
| 数据来源 | `os.ReadDir` 逐层列举 | 目录树的第一层就够用；预扫整棵树在大工作区上要几秒 | 每次展开一次往返 |
| 条数上限 | 单层 500 条 | 把整个盘列举给前端只会让界面卡住 | 超大目录末尾有截断 |
| 可见性 | 隐藏条目（`.` / `$` 前缀）不进列表 | 给办公用户看的浏览器里不该出现系统隐私文件 | 想看 `.git` 得用别的工具 |
| 排序 | 目录在前，其余按名字忽略大小写 | 目录在前让「往哪钻」先于「打开哪个」 | 文件名大小写混合时顺序不直观 |
| 归属目录 | 会话级工作目录优先，退回全局工作目录 | 会话里的改动发生在会话自己的目录里 | 目录切换要重新拉一次 |

`service.FileService` 是这一块唯一的数据出口，`api` 只做参数与响应。
工作目录校验只在这里做一次：复用 `pkg.SafeJoin`，越界直接 `1004`。

## 契约

| 方法 | 路径 | 出参 |
|---|---|---|
| GET | `/api/v1/files?path=&session_id=` | `FileListVO`：`path`（规范化后的相对路径）+ `entries[]`（`name` / `dir`） |

`path` 为空表示工作区根；`session_id` 决定根是哪个目录，没给则用全局工作目录。
目录在前、名字排序，`dir=true` 的是目录。

错误码：`1001` 还没设工作目录；`1004` 路径越界（绝对路径 / `..`）；
`1005` 目录不存在或读不出来。

## 关键流程

1. 用户在输入框打 `@` → 打开引用面板
2. 面板首次要数据 → `GET /files`，渲染工作区根那一层
3. 点目录 → 再要一层，路径追加；点文件 → 记下路径并关面板（`↑↓` 选中、`Enter` 确认）
4. 发送时附件分两类走：图片把 base64 交给 PI 的 `prompt.images`；其余只把**相对路径列进正文**。
   WorkBaby 不代读文件内容——读它是助手自己的工具该做的事，列路径就够它去读
5. 附件数量不设上限：待发行超过两行就在区内滚动，不把输入框顶出屏幕
6. 落到工作区之外的路径标红并拦住发送：读了也读不到，静默收下只会让用户以为发出去了

附件路径同样受 `SafeJoin` 约束：越界的文件**不收**，界面上标红说明原因。
只有 `/files` 列举这条路径本身会因为越界报 `1004`；发送消息不因为单个附件失败而失败。

## 不变量

| 不变量 | 锁死原因 |
|---|---|
| 路径必须落进工作目录（`pkg.SafeJoin`） | 工作区之外的目录不该被这个入口列举 |
| 单层 500 条截断 | 无上限列举在 `C:\` 这类根上会把前端卡死 |
| 隐藏条目不进列表 | 给办公用户的界面不出现系统隐私文件 |
| 附件只读不写 | 这一层的职责是「选文件」，不是「改文件」 |
| 会话级目录优先 | 用全局目录会列举到与本次会话无关的文件 |

## 取舍

- **只列举一层**：实现与响应都最简单，代价是深路径要逐层点开；
  预扫整棵树省这几次往返，但换来的是首屏几秒的等待与一份会过期的缓存
- **不读内容**：内容读取与展示是差异视图（[08](08-workspace-git.md)）与附件链路（[02](02-session.md)）的职责；
  合进来会让「浏览」与「读」两种语义缠在一起，截断规则也要各写一套
- **隐藏条目直接过滤**：省一层「要不要显示」的判断；代价是高级用户在这个面板里看不到 `.git` 与配置文件
