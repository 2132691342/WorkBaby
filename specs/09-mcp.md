# 09 · MCP 外部工具

## 三份真相

| 问题 | 真相在哪 |
|---|---|
| 配了哪些服务 | `~/.pi/agent/mcp.json`（全局）+ `<项目>/.pi/mcp.json`（项目级） |
| 谁连上了、暴露了哪些工具 | `pi mcp list --json` |
| 模型能直接调到哪些 | 会话里的工具声明（`toolsAdded`） |

WorkBaby 不维护自己的 MCP 清单：用户用 `pi mcp add` 加的，打开界面就该看到。

## 界面

- **服务卡片**：名字、范围、暴露档、传输方式、在线状态、工具数、错误原文；
- **配置原文编辑**：全局与项目两份分开，保存前做 JSON 语法与 `mcpServers` 结构校验，
  不通过一个字符都不写；
- **动作**：登录（OAuth，浏览器里完成）、登出、删除（走 `pi mcp remove`）、重连（重启 PI）。

## 暴露档（exposure）

| 档 | 含义 |
|---|---|
| `direct` | 工具直接声明给模型 |
| `codemode`（缺省） | 只在 codemode 脚本里可调 |
| `deferred` | 连 codemode 都不列，只能被 `tool_search` 找出来 |

因此「工具页」里列为 `mcp__<server>__<tool>` 的不一定都在模型的 tool 列表里——
它们是该服务提供的全部工具，可见范围由暴露档决定，界面上写明。

## 保存与生效

```
编辑原文 → 校验 → 原子写盘 → 重启全部 PI 进程
```

mcp.json 是启动期读的：写完不重启等于没改。重启会中断正在跑的对话，因此界面在按钮上说明这一点。

## 登录

OAuth 服务（远程 streamable-http）首次使用要授权：

1. 点「登录」→ `pi mcp login <server>`，它在浏览器里打开授权页；
2. 完成后点「重连」→ `pi mcp list` 会显示 `connected` 与工具清单。

凭据存在 PI 的 `mcp-auth.json`，WorkBaby 不读也不写它。

## 取舍

- **原文编辑而不是结构化表单**：MCP 配置的字段因客户端而异（`headers` / `timeout` / `oauth*`），
  结构化表单迟早漏字段；代价是要求用户会写 JSON（模板按钮兜住第一次）。
- **在线状态来自子进程**：唯一可信；代价是每次打开面板要跑一次 `pi mcp list`（约 1 秒，含连接）。
- **不做工具级开关**：PI 的可见性由暴露档决定，在 WorkBaby 里再记一层开关只会与 PI 分叉。
