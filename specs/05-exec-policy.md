# 05 · 命令执行策略

## 定位

`powershell` 工具让助手能跑系统命令（pip、git、脚本），是能力上限也是最大风险点。
策略两条：**命令类必须过审批门**（yolo 档整体放行）+ **环境可控**。

## 规则

| 规则 | 说明 |
|---|---|
| 内置运行时优先 | 子进程 PATH 首位插入内置 Python 目录，`python` / `pip` 优先解析到内置解释器 |
| 超时 | 默认 120s，上限 600s，超时杀进程树并返回已产出内容 |
| 输出上限 | 统一走 `tool.CutTail`：2000 行 / 50KB 双上限，保留结尾，超出落临时文件并把路径与丢弃量告诉模型 |
| 编码归一化 | GBK 输出统一转 UTF-8（Windows 命令行默认 GBK；已是合法 UTF-8 的原样返回） |
| 审批 | `powershell` 与 `python` 要求审批；yolo 档整体放行（见下表） |
| 无 profile | `-NoProfile -NonInteractive`：不加载用户 profile，不弹交互提示 |

进程树终止用 `cmd.Cancel` + `WaitDelay`：超时或用户点停止时杀掉子进程，
最多等 3 秒让管道收尾，避免留下孤儿进程占着文件。

## 审批档位

| 档位 | 行为 |
|---|---|
| ask（默认） | 写文件 / 跑命令 / 跑脚本都问 |
| auto_edit | 只读随便跑；写文件与改文件不问；命令与脚本仍然问 |
| yolo | 全部不问直接跑（用户自担风险） |

三档只决定「哪些工具需要审批」，**不改变工具面**——不做「只读档就把工具藏起来」，
那会让模型突然找不到工具并反复重试。

## 输出形态

跑完返回一段合并文本（stdout + stderr）+ 标题里的耗时。**非零退出码不算工具错误**：
命令跑没跑成功是事实，由模型自己解读（`grep` 无匹配、`git diff --exit-code`
都会返回非零）；只有执行层失败（找不到 shell、启动被拒、超时、被停止）
才标为工具错误。

## 取舍

审批只拦「命令与脚本」，不拦读文件：读是最高频的动作，弹窗会训练用户无脑点放行。
命令输出里风险词（remove-item / format- 等）只做分级展示，不做黑名单拦截——
关键词匹配的误报率太高，真正的闸门是审批卡本身。
