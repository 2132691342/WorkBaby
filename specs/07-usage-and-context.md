# 07 · 用量与上下文

## 用量从会话文件来

每条 assistant 消息都带 `usage`（`input` / `output` / `cacheRead` / `cacheWrite` / `totalTokens` / `cost`）。
仪表盘就是把这些行按时间窗口加起来：

| 聚合 | 维度 |
|---|---|
| 总量 | 区间内全部调用的 input / output / cached / total / cost / calls |
| 按天 | 消息时间戳（毫秒）落成本地日期，缺的日子补 0 |
| 按模型 | `provider` + `model`（同名模型被多个服务商提供时分开展示） |
| 按会话 | 每个文件一行，点开直达那段对话 |

`usage` 条目（不参与上下文的那种，例如缓存保温）也计入花费与 token。

**不单独落一张用量表**：会话文件里已经有一份更权威的（含 PI 自己发起的调用）。

## 缓存命中率

`cached / input`。命中量理论上不会超过输入量；上游按「未命中口径」报 input 时后端补回，
前端再钳到 100%——读数超过 100% 只会让人以为统计坏了。

## 花费

按 `models.json` 里模型条目的 `cost`（美元 / 百万 token）估算。没填单价就是 0。
它用于「看趋势、找异常」，不用于对账：促销价、阶梯价、已经计费但没落盘的重试都不在里面。

## 上下文水位

输入区那个环回答「离开始整理有多近」：

```
usable = window - reserve        # reserve 由 PI 的压缩阈值给
ratio  = used / usable * 100
```

| 数据源 | 时机 |
|---|---|
| SSE `chat:context` | 每轮结束由 PI 的 turn_end 触发 |
| `chat:done` 的 `usage.context` | 收尾校准（SSE 的最后一次读数不含最后一轮回复） |
| 会话快照 | 打开 / 切换会话时回填，不必等下一轮 |

窗口来自 `models.json` 里模型的 `contextWindow`；查不到时为 0，界面读数加「约」前缀。
≥80% 转警告色、≥95% 转危险色。

它是一个**裸读数**（环 + 数字），不套描边胶囊：底栏已有模型 / 思考两个 chip，
再给水位加一个盒子就是第三个「看起来能点」的框，而它只读。

## 截断

`stop_reason = length` 表示撞了模型自己的输出上限：界面给一条警告 + 「继续」按钮，
并报出本轮实际下发的输出预算（`max_tokens`）——说清撞的是哪个上限，用户才知道该调额度还是换模型。

## 取舍

- **只读会话文件**：不会与 PI 的账分叉；代价是统计要扫全部会话（几十个文件、毫秒级）。
- **花费是估算**：不引第三方计价表；代价是与账单有偏差（文档里明说）。
- **水位分母是可用预算**：与 PI 开始整理的位置同口径；代价是与「占整窗口」的读数不同，需要一句 tooltip 解释。
