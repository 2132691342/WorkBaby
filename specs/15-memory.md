# 15 · 长期记忆

设计取舍：**不做情景 / 语义 / 程序分类，也不做 run 后自动沉淀**。
长期记忆就是一份人能直接编辑的 Markdown 文件，FTS5 只是它的派生索引。

## 1. 存储

单一真相源：`{home}/memory/{sessionID}/MEMORY.md`
（会话绑定工作区时放在 `<工作区>/.workbaby/memory/{sessionID}/`）。

```markdown
# 长期记忆

## 用户偏好
- 回复用中文

## 事实
- 项目用 Go 1.24

## 流程
- 提交前跑 go test ./...

## 项目约定
- 错误码按段位分配
```

| 约束 | 值 |
|---|---|
| 固定分节 | 用户偏好 / 事实 / 流程 / 项目约定；未知分节归一到「事实」 |
| 条目上限 | 200 条（写满丢最旧一条） |
| 单条长度 | 400 rune |
| 去重 | 重复条目幂等跳过 |

## 2. 写入时机

| 路径 | 说明 |
|---|---|
| `memory_write` 工具 | **唯一由 Agent 触发的写入路径**（模型主动追加） |
| 设置页 | 增删与整篇覆盖 |

**刻意不做 run 后自动抽取**：自动沉淀会把噪声写进记忆，且难以修正。
要记住什么由用户或模型明说。

## 3. 检索

FTS5 虚拟表 `memory_fts(section, content, tokenize='trigram')`，全量重建（事务内删旧插新）。

| 环节 | 实现 |
|---|---|
| 查询 | `MATCH` + `bm25` 排序；查询串按词加引号以 OR 连接 |
| 短查询兜底 | 短于 3 字（trigram 窗口）的查询退化为子串扫描——中文短词漏结果是记忆能力最容易踩的坑 |
| 打分 | 不是 bm25 原值，而是**名次递减**（`len(rows) - idx`），保证跨查询可比较 |
| 兜底打分 | 命中次数×10 − 文本长度/100 |

## 4. 注入

能力注册表在 run 前按用户输入检索（`Search(input, 6)`）：

| 情况 | 行为 |
|---|---|
| 有命中 | 作为 `Section` 注入（`Order=40`），Title 提示可用 `memory_write` 追加 |
| 无命中 | 回退全文并截断到 4000 rune |

记忆开关在设置页（`system_settings` 的 `SettingKeyMemoryEnabled`）；
关闭后既不注入也不暴露 `memory_write` 工具。

## 5. 与知识库的区别

| | 记忆 | 知识库 |
|---|---|---|
| 内容 | 简短、稳定、关于用户与项目的事实 | 长文档 |
| 写入 | 逐条追加 | 文档级导入（文件 / URL / 文本） |
| 检索单位 | 条目 | 分块（500 字，重叠 50） |
| 归属 | 会话 | 全局 |
| 数据形态 | 单一 Markdown（人可直接编辑） | DB 行 + 分块 |

## 6. 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 单一 MEMORY.md + FTS5 派生索引 | 数据可迁移、可手工修正；索引丢了重建即可 | 无向量语义检索（靠 FTS + 短查询子串兜底） |
| 条目上限自收敛（写满丢最旧） | 注入段不会无限膨胀 | 早期条目会被挤掉（重要内容需用户手动固化） |
| 会话级归属 | 不同项目的记忆互不串味 | 跨会话的通用偏好需重复记录（或沉淀成全局规则 / 技能） |
| 不做自动沉淀 | 记忆里只有明确写入的内容，无噪声 | 用户与模型必须显式写入 |
| 短查询子串兜底 | 中文短词不漏（trigram 的必然限制） | 短查询时退化为扫描（数据量上限 200 条，代价可接受） |
| 名次递减打分 | 跨查询可比较、可预测 | 丢失 bm25 的绝对相关性信息 |
