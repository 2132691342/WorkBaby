# 18 · 桌面壳：窗口、托盘与单实例

> 形态锚定：Wails v2 + WebView2 单窗口（窗口形态不分裂到桌宠）。
> 本 spec 描述桌面侧三类能力：主窗口系统集成、托盘常驻、单实例保护。

## 1. 窗口形态

只有一种窗口形态——主窗口。三栏布局（侧栏 + 主区 + 右栏面板 / 设置页两栏 / 主页两栏），自适应缩放。

| 项 | 取值 |
|---|---|
| 最小尺寸 | 960×640 |
| 关闭默认动作 | 可配置：直接退出 / 关闭到托盘（设置页） |
| 标题栏 | 保留原生 + 自绘按钮（设置页可切） |

### 为什么单窗口

多窗口需要 Wails v3；单窗口共享同一前端上下文（store / SSE 连接 / 主题）能省掉一套跨窗口状态同步。

## 2. 系统托盘

`internal/tray`（Win32 原生实现，非 Windows 提供空实现）。

| 菜单项 | 行为 |
|---|---|
| 显示 / 隐藏主窗口 | 切换可见性 |
| 退出 | 真正退出（区别于关闭窗口） |

关闭到托盘可配置（设置页）。

## 3. 单实例保护

`internal/singleinstance`：命名互斥 + 本地 TCP IPC。

| 步 | 行为 |
|---|---|
| 1 | 尝试创建命名互斥体 |
| 2 | 已存在（第二次启动）→ 通过本地 TCP 把参数（如文件路径）发给已有实例 |
| 3 | 已有实例收到后唤起窗口并打开对应文件/会话 |
| 4 | 新进程退出 |

配合文件关联（`.md / .txt / .pdf` 双击唤起）与 `app:open-file` 事件。

## 4. 双通道与系统能力

| 通道 | 承载 |
|---|---|
| HTTP `/api/v1` + SSE | 全部业务 API 与实时事件（可浏览器调试、可 curl 复现、可重放） |
| Wails 绑定 | 仅系统能力：文件对话框、打开外链、剪贴板、托盘、窗口控制 |

`app:*` 事件经 `bindEventBridge` 转发到 Wails；`chat:*` **不转发**——SSE 已覆盖，
避免每条增量在 run goroutine 上多做一次序列化与 IPC。

## 5. 生命周期

| 阶段 | 动作 |
|---|---|
| 启动 | 单实例检查 → `api.Handler.Startup`（装配）→ 启动内嵌 HTTP Server（随机端口）→ 发 `app:ready{server_port}` |
| 运行 | 托盘常驻；窗口可关闭到托盘 |
| 退出 | 关闭 MCP 子进程 → 停止 worker → 保存配置 → 释放互斥体 |

## 6. 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 单窗口共享前端上下文 | 无跨窗口状态同步；store / SSE / 主题一处维护 | 桌面只有「主窗口 + 托盘」两个面，工作流深度受限于同一窗口 |
| 业务走 HTTP + SSE | 浏览器可调试、可 curl 复现、可断线重放 | 需自建端口发现与契约校验 |
| Wails 仅承载系统能力 | 业务与桌面壳解耦；前后端可独立演进 | 双通道边界需要清晰约定 |
| 托盘 Win32 自研 + 非 Windows 空实现 | 无 CGO、无额外依赖；跨平台编译不破 | 仅 Windows 可用托盘 |
| 单实例走本地 TCP IPC | 可传参（文件路径）并唤起已有实例 | 需要端口与互斥体两套机制配合 |
