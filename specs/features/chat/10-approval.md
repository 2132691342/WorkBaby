# 10 · 审批与补问

护栏链的 `ask` 决策落到 `ApprovalService`，两种用途共用同一套机制：

| 类型（`Kind`） | 触发 | 用户动作 |
|---|---|---|
| `approval` | 工具策略门判定需人工确认 | 拒绝 / 本会话允许 / 仍要批准 |
| `input` | `request_input` 工具缺关键信息 | 提交答复 / 跳过 |

## 1. 阻塞式等待

聊天 run 的审批门**阻塞当前 run** 等用户决策，前端渲染 `chat:approval` 卡片。
后台任务用 `grantApprover`（只吃免审授权，不弹窗）——无人值守场景不能挂起。

```
Approver.Approve(ctx, call, risk) bool
```

调用链：`PolicyGuard` → `coreApprover` → `ApprovalService.Approve` → 阻塞 select。

## 2. 三种决策

| 决策 | 落库 | 语义 |
|---|---|---|
| 拒绝 | 记 `denied` | 返回拒绝回执（`Refused`），模型可改道 |
| 本会话允许 | 记 `approved` + 落 `approval_grants` + 按 run 记账 | 同命令后续免审 |
| 仍要批准 | 记 `approved` | 仅本次放行，不落授权 |

**不可逆风险（`irreversible`）永不提供「本会话允许」**：`can_remember` 恒为 `false`，
前端据此隐藏该选项。

## 3. 持久化与跨重启

未决记录落 `approval_records`（含 `Command` / `Risk` / `ExpiresAt`）。

| 阶段 | 行为 |
|---|---|
| 挂起 | 记录落库 + 广播 `chat:approval` |
| 重启 | `RearmPending` 把窗口延长到 24h；前端刷新仍能拉到卡片 |
| 决策 | 进程内已无等待者时，`Decide` 落库并触发 `ResumeRun(runID)` → 从检查点恢复 |
| 续跑重放 | 同一调用带 `resumed` 标记重新发起 → 已决记录**快速放行**（不再询问） |
| 消费 | 放行后置 `consumed`，防止一次性审批被静默复用 |

**一次性语义**：已消费的记录不再生效——同命令再次调用（非续跑）必须重新询问，不能演变成永久免审。

## 4. 免审授权（approval_grants）

「本会话允许」的持久化授权跨重启生效（`LoadGrants`）。

| 机制 | 行为 |
|---|---|
| 记账 | 授权按 run 归属记录 |
| 回滚 | run 以 `error` / `cancelled` 收尾时，回滚该 run 扩出的授权（未验证的工作不保留免审） |
| 不可逆例外 | `irreversible` 不参与授权（每次必问） |
| 撤销 | `POST /chat/approval-grants/:id/delete` |

**为什么失败要回滚**：授权的前提是「用户认可这类操作在本会话内可信」。
若该 run 最终失败，说明这次工作并未被验证，保留免审等于把风险留给后续 run。

## 5. 补问（input）

`request_input` 工具走同一套机制（`Kind=input`）：

| 阶段 | 行为 |
|---|---|
| 提问 | 落 `pending` 记录 + 广播 `chat:approval{risk:"input_required"}`（`can_remember` 恒 false） |
| 答复 | `Answer(id, text)` 回填 → 触发续跑 |
| 跳过 | `Skip(id)` → 续跑重放得到「未回复」语义 |
| 续跑复用 | 重放同一提问时直接复用已落库回答，不二次打扰 |

超时（默认窗口）与取消（会话取消）都会唤醒阻塞的等待者。

## 6. 取消与会话清理

| 场景 | 行为 |
|---|---|
| 新 run 启动 | `prepareRun` 先 `CancelSession` 清掉同会话遗留挂起审批（旧卡的决策对象已不存在） |
| 会话取消 | 内存等待者随取消醒来（返回 false），记录置 `cancelled` / `denied` |
| 应用重启 | `ReapInterrupted` 处理卡在 `streaming` 的消息 |

## 7. 拒绝回执的可解释性

拒绝不是故障，而是给模型的**回执**：

| 情况 | 回执文案来源 |
|---|---|
| 用户拒绝 | 「用户拒绝执行: <命令>」 |
| 审批门带 `DenyReason()` | 用门自述原因（如 grantApprover 的「缺少免审授权」） |
| 策略拒绝 | 「策略拒绝执行: <工具名>」 |
| 注入检测 | 「参数含伪工具调用标记，已拒绝执行」 |
| 路径不受信任 | 「路径不受信任: <目录>（<原因>）」 |

模型读到原因后可改道（换工具 / 换参数 / 向用户说明），而不是整轮失败。

## 8. 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 阻塞式等待（非轮询） | 决策到达即时恢复，无忙等 | run 期间占用一个 goroutine |
| 审批持久化 + `consumed` 标记 | 跨重启不丢决策；一次性审批不被复用 | 多一张表与一套恢复逻辑 |
| 失败 run 回滚授权 | 未验证的工作不保留免审 | 用户需重新授权（安全优先） |
| 不可逆恒需审批 | 不可逆操作永不免审 | 重复确认的打扰（用一次性拒绝/批准缓解） |
| 补问与审批共用机制 | 复用同一条恢复链路，实现收敛 | `input` 语义需靠 `Kind` 区分 |
| 拒绝是回执不是错误 | 长任务不因一次拒绝中断 | 每个消费方必须正确区分「拒绝」与「失败」 |
