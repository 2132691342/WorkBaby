# 08 · 网络与文档工具

## 1. 联网检索

| 工具 | 能力 | 约束 |
|---|---|---|
| `websearch` | 网页搜索：默认 DuckDuckGo **免 Key**，HTML 解析 | 结果条数与摘要长度有上限 |
| `webfetch` | 抓网页正文并抽取可读文本 | 响应 ≤5MB |
| `http` | 通用请求 | **仅 GET / POST**（与全局方法白名单一致） |

### 为什么默认 DuckDuckGo

免配置是「开箱可用」的前提：用户不需要为搜索单独申请 API Key。
设置页可切换搜索引擎（`/settings/websearch`）。

### 抽取策略

`webfetch` 不返回原始 HTML（含大量导航与脚本噪音），而是抽取正文文本：

| 步 | 处理 |
|---|---|
| 1 | 按 `Content-Type` 与响应体嗅探编码（含 meta charset 与 BOM） |
| 2 | 剥离 `script` / `style` / `nav` / `footer` 等非正文块 |
| 3 | 正文块降级为纯文本（保留段落结构与列表语义） |
| 4 | 按 rune 截断（避免单页淹没上下文） |

## 2. 文档解析

`doc_reader` 抽取本地文档正文，供模型阅读用户资料：

| 格式 | 实现 |
|---|---|
| `pdf` | `ledongthuc/pdf` 逐页抽文本 |
| `docx` | 解压 OOXML，抽 `word/document.xml` 文本节点 |
| `html` / `htm` | 同 `webfetch` 的正文抽取 |
| `csv` | 按分隔符解析为表格文本 |
| `json` | 校验并美化（缩进）后返回 |
| `txt` / `md` | 直读 |

输入路径限定工作区沙箱（同文件工具）。

### 为什么不做 OCR

PDF 只抽文本层。扫描件（图片型 PDF）需要 OCR 引擎，属重量级依赖——
当前定位为「抽取可读文本」，扫描件由用户先行转换。

## 3. 知识库检索入口

`knowledge_search` 是模型访问本地知识库的**唯一入口**：

| 特性 | 说明 |
|---|---|
| 返回结构 | 带出处的片段（文档名 + 分块位置 + 相似度/命中说明） |
| 结构化数据 | `ToolResult.Data["hits"]` 供前端渲染来源卡（可展开全文） |
| 检索实现 | FTS5 trigram + 短查询子串兜底（详见 `../capability/16-rag.md`） |

## 4. 网络工具的护栏

| 层 | 机制 |
|---|---|
| 风险档 | `RiskNetwork`；`default` / `auto_edit` 模式下需审批 |
| 方法白名单 | `http` 工具仅 GET / POST（由 `pkg/httprules.go` 统一裁决） |
| 体积上限 | `webfetch` ≤5MB；`http` 同；超限中止 |
| 超时 | 走 `ExecOptions.Timeout`（默认 5 分钟） |
| 域名提示 | URL 出现在审批卡上，用户可判断目标 |

## 5. 内置运行时与网络

联网工具不经内置运行时（直接走 Go 的 HTTP 客户端），
内置 python 主要服务 `exec` 与技能脚本。

## 6. 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 默认免 Key 搜索 | 开箱可用，无配置门槛 | 结果质量依赖 HTML 结构（搜索引擎改版需适配） |
| 抽正文而非返回 HTML | 上下文不被导航与脚本噪音淹没 | 复杂 SPA 页面（内容由 JS 渲染）可能抽不到正文 |
| 仅 GET / POST | 与全局方法白名单一致，降低误用面 | 需要 PUT / DELETE 的 API 无法直接调用 |
| 体积上限 5MB | 防大响应拖垮内存与上下文 | 超大文档需用户先本地处理 |
| 不做 OCR | 无重量级依赖 | 扫描件不可读 |
| `knowledge_search` 单一入口 | 检索逻辑收敛，改动面小 | 新增检索模式需改该工具 |
