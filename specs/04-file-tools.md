# 04 · 文件工具

## 定位

文件三件套 + 目录浏览，是「能干活」的最低保障。
两条安全底线：**工作目录之外一律拒绝**、**写之前必须读过**。

## 安全规则

| 规则 | 实现 |
|---|---|
| 路径穿越拒绝 | `pkg.SafeJoin` 解析真实路径后必须仍在 workspace 内，否则 1004 |
| 符号链接防穿越 | 目标不存在时解析最深的存在祖先再拼接，`..` 与链接都暴露在判定里 |
| Unicode 路径规整 | `pkg.NormalizePath` 先把不换行空格等规整成普通空格、剥掉前导 `@` |
| 写前必读 | 目标已存在且本会话没读过 → 拒绝（1009），防止盲写覆盖 |
| 读后标记 | read / write 成功后把绝对路径记入 `Deps.Reads`；edit 只消费标记（改之前必须读过），不刷新它 |
| edit 唯一性 | `old_text` 在当前文本中出现次数 ≠ 1 → 拒绝（1010） |
| 换行与 BOM 保持 | edit 剥 BOM → 探测行尾 → 归一到 LF 替换 → 按原行尾写回 |

### 为什么要有 Unicode 规整

办公用户从微信、网页、Word 里复制路径时，经常带进 U+00A0、U+3000 全角空格
或不换行空格。模型如实传过来，`os.Open` 找不到文件——错误信息对新手毫无意义。
规整让这类「明明有这个文件却读不到」不会发生。

## read

| 参数 | 说明 |
|---|---|
| path | 相对工作目录或绝对路径 |
| offset | 起始行号，从 1 开始 |
| limit | 读取行数，默认 2000 |

- 输出带行号（`   N\tcontent`），空文件给明确提示而不是空白
- 解码统一走 `pkg.DecodeText`：UTF-8 / UTF-16（含无 BOM 启发式）/ GBK 都归一，
  记事本另存的 Unicode 文件与中文 CSV 不乱码
- 二进制判定走 `pkg.LooksBinary`：命中原生 NUL 字节即拒绝并说明，不把乱码塞进上下文；
  带 BOM 的 UTF-16 文本是合法文本，不会被误判
- 截断时给出**可执行**的续读提示：`……（共 5000 行，已显示第 1-2000 行；用 offset=2001 继续读）`
- **超过 32MB 走流式取页**：逐行扫描只保留目标区间，不为整文件分配内存。
  全量读进内存只为了截断前 2000 行，读一个几 GB 的日志会把助手连同界面一起卡住。
  大文件路径按 UTF-8 处理（超大文本里 GBK 属少数场景），单行上限 16MB

## write

- 全量覆写，父目录不存在自动创建
- 新文件无需先读；已存在文件必须先读过
- 结果明确区分「新建」与「覆盖」——覆盖是危险操作，要让模型和用户都看见
- **原子写**：先写同目录临时文件再 rename。磁盘写满或进程中途退出时原文件保持完整；
  助手写的是用户的真实工程文件，半截内容比写失败更糟

## edit

- 输入 `edits[]`，逐条 `old_text → new_text`
- 严格按顺序应用，任一条失败整体失败（不落盘）
- 唯一性按**已应用的前序改动**重新判定：第二条要能在第一条改完之后的文本里唯一定位
- 返回改动处前后 3 行的 diff 片段，够看懂又不占篇幅

## 错误码

文件与路径类失败统一落 1000 段：`1005` 不存在 / 读取失败、`1008` 目标是目录、
`1009` 写前必读、`1010` edit 未命中或没有实际改动、`1011` 打开目录失败；
工作目录相关的 `1002` / `1003` 由 service 层给出。完整清单见
[`docs/ERROR-CODES.md`](../docs/ERROR-CODES.md)。

## ls / find / grep

| 工具 | 参数 | 说明 |
|---|---|---|
| ls | path | 单层列表，目录在前（目录名带 `/`）；不做隐藏过滤，@ 引用面板的列举入口另按自己规则过滤 |
| find | pattern, path? | 递归通配，尊重 .gitignore |
| grep | pattern, path?, glob? | 正则搜索，输出 `file:line: text`，命中数封顶 |

搜索类工具统一剪枝：命中 `.git` 整棵跳过、命中忽略规则的目录整棵跳过、
结果攒够上限就停手——不逐个文件进去再丢。

两条防卡死闸门：`glob` 匹配走 `matchName`（`**/` 前缀按基名匹配，
模型习惯写的 `**/*.xlsx` 与 `*.xlsx` 都命中）；grep 对 >8MB 的单文件直接跳过
并计入截断提示——搜一个几 GB 的日志/数据文件会把整文件读进内存，
是「助手卡死」的典型来源。命中行截断到 500 字符（压缩过的 JS 一行能有几十万字符）。

## 取舍

不做 delete / move / copy：个人助手场景里不可逆操作交给用户自己或
`powershell`（需审批），工具面越小越安全。
