# 03 · 技能

## 技能是什么

一个目录 + 其中的 `SKILL.md`。frontmatter 给路由信息（`name` / `description`），正文是方法论。
PI 启动时把「名字 + 描述 + 路径」放进系统提示，模型觉得需要时才去读全文。

## 三个来源

| 来源 | 目录 | 界面能做什么 |
|---|---|---|
| 我的技能 | `~/.pi/agent/skills/` | 启用 / 停用 / 删除 / 导入 / 查看 |
| 工作区 | `<项目>/.pi/skills/`、`<项目>/.agents/skills/` | 只读（别人的文件） |
| 插件包 | 包目录下的 `skills/`（或 `package.json` 的 `pi.skills`） | 只读（随包装卸） |

同名时优先级：工作区 > 包 > 用户目录。注册表按 `name@source` 建键，界面拿到的是这个 id。

## 启停 = 移目录

PI 只扫 `skills/`。所以「停用」是把目录移到同层的 `skills.disabled/`：

```
~/.pi/agent/skills/foo/          → 启用（模型可见）
~/.pi/agent/skills.disabled/foo/ → 停用（模型不可见，界面仍可读正文）
```

搬目录而不是记一个开关，好处是**对模型真的不存在**；代价是工作区与包里的技能搬不了，
界面如实拒绝并告诉用户该去动哪里。

## 导入

支持一个 `SKILL.md` 或 `.zip`：

- 定位到 SKILL.md 后，把**整个所在目录**复制进 `skills/<name>/`——脚本与素材一起走；
  只复制 SKILL.md 会让带脚本的技能在运行期找不到自己的文件；
- 同名自动加序号（`foo-2`）；
- zip 解压前做路径穿越与符号链接检查，单文件与总量都有上限。

## 正文查看

按 `Location` 直接读磁盘，停用的技能也能打开——停用是「对模型隐形」，不是删掉。

## 与 PI 的分工

- 技能的**解析与注入**全在 PI 里；WorkBaby 只解析 frontmatter 做界面展示；
- `frontmatter` 里可能有列表、布尔、数字（`when_to_use`、`version`…），因此用 `map[string]any`
  而不是 `map[string]string`：用后者会让整份 YAML 解析失败、技能被静默跳过。

## 取舍

- **移目录启停**：语义干净；代价是不能跨磁盘移动，且用户在别处手动搬走后界面要重扫才能对上。
- **整目录导入**：技能能带脚本；代价是大技能包会占空间（上限 256MB 解压量）。
- **包内技能只读**：避免 WorkBaby 改动别人包里的文件；代价是想关掉某个包技能只能停整个包。
