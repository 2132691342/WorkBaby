# 03 · Skill 系统

## 定位

Skill = 一段按需注入的领域知识（prompt 素材），不是可执行插件。
「秘籍」：让助手在特定场景按固定套路干活。纯文本，**安全面为零**——
不产生任何执行行为，新手也能自己写。

**文件与内核命令行共用同一批目录**：全局技能就在 PI 的 `<agent-dir>/skills/`，
工作区技能在 `<workspace>/.pi/skills/`——用户在命令行里放的技能，界面立刻看得见；
界面里建的技能，命令行也能当斜杠命令用。
但**清单进模型上下文的通道只有一条**：PI 自己扫目录，把启用中的技能渲进系统提示
（`<available_skills>`）。WorkBaby 不再渲染第二份——两份清单就有两个「现在到底看得见哪些」，
停用在其中一个里不生效。

## 文件格式

```
{数据目录}/pi-agent/skills/{name}/SKILL.md        # 全局（= PI 的 <agent-dir>/skills/）
{workspace}/.pi/skills/{name}/SKILL.md            # 工作区级
```

`<agent-dir>` 由 `PI_CODING_AGENT_DIR` 指向 `{数据目录}/pi-agent`（见 [18](18-pi-bootstrap.md)）。

**不预置任何技能**：要用什么套路由用户自己写或导入，应用只提供管理入口。
预置一批「看起来有用」的技能，实际是把作者的选择塞进每个人的目录，
而它们大多一辈子不会被展开。

```markdown
---
name: weekly-report
when_to_use:
  - 周报
  - 写周报
description: 按公司模板把本周工作整理成周报。
---
（正文：给模型看的操作指引，Markdown）
```

`name`（小写字母 / 数字 / 连字符，≤64）不合规才拒绝；`name` 与 `description`
缺失时有兜底（分别回退目录名与正文首行）。`when_to_use` 是可选触发词列表。
frontmatter 允许混合标量、列表与行内数组（解析进 `map[string]any`，
收窄成字符串表会让整份 YAML 解析失败、技能被静默跳过）。

这套 frontmatter 格式与 PI 的 skill 规范一致，同一个文件两边都能读。

## 两个来源与优先级

| source | 目录 | 同名冲突 |
|---|---|---|
| global | `{数据目录}/pi-agent/skills/` | 低 |
| workspace | `<workspace>/.pi/skills/` | 高 |

`List()` 全部列出并带 `source`，让用户看得见「这个技能是从哪来的」。
工作区切换 = 先 `DropSource(workspace)` 再装入新目录，上个项目的技能不会残留。

## 注入方式

三条路径，都指向同一个 SKILL.md：

| 入口 | 机制 |
|---|---|
| 模型自己判断该用 | PI 扫目录，把启用中的清单（name / description / 路径）渲进系统提示，模型按路径 `read` 正文（渐进式披露） |
| 界面点技能卡片 | WorkBaby 把正文拼进当前这条用户消息 |
| 斜杠命令 | 同「点卡片」，WorkBaby 侧展开 |

**界面点卡片走消息注入而不是斜杠命令**：PI 的 `/skill:name` 是 TUI 的输入语法，
RPC 的 `prompt` 命令里它会被当作普通文本。要立刻按某个技能干活，
把正文拼进 `message` 是这个协议下唯一可靠的方式。

正文注入后在 PI 的 JSONL 里仍是一条普通 user 条目——不是新消息类型，
投影与导出都不用特判。

## 管理

| API | 说明 |
|---|---|
| GET /skills | 列表（含来源与启停状态） |
| POST /skills | 新建：写 `SKILL.md` 到全局技能目录 |
| POST /skills/import | 从磁盘导入 `{paths[]}`：单个 SKILL.md、含它的文件夹，或装满技能子目录的目录（只扫一层）；同名自动追加 `-2` 序号不覆盖；返回 `{imported, skipped[]}`（skipped 是没导进来的条目与原因，界面要能看到，静默丢弃会让用户以为文件放错了） |
| POST /skills/import-zip | 导入压缩包 `{filename, data}`（zip 字节 base64）：解压到临时目录后走同一条定位复制链路；条目路径经 SafeJoin 校验防穿越，单文件 64MB / 总量 256MB 双限流 |
| POST /skills/toggle/:id | 启停 |
| GET /skills/content/:id | 正文预览 |
| POST /skills/delete/:id | 删除（只删全局技能；工作区技能属于用户项目文件，只从界面摘除） |

### 启停的真实实现

PI 只看目录里有什么，没有 "enabled" 标志位。所以**停用 = 把技能目录移出 PI 的扫描范围**：

```text
{agent-dir}/skills/{name}/            ← 启用：PI 看得见
{agent-dir}/skills.disabled/{name}/   ← 停用：对模型不存在，对界面仍列得出
```

启停状态没有第二份 KV 落库：真相就是文件在哪个目录，内存注册表与界面列表
都由两区扫描得出，不存在「KV 说停了、目录说没停」的缝隙。
停用的技能正文照常可读、可一键恢复；目标位已有同名报 8111。

**工作区技能不可从界面停用（8110）**：那是用户项目里的文件，界面替他搬文件夹
等于改他仓库内容——需要的话用户自己在项目里动。

生效时机：PI 在进程启动与会话切换时重扫目录，下一轮对话自然反映，不需要重启应用。

## 不变量

| 不变量 | 锁死原因 |
|---|---|
| 技能目录 = PI 的技能目录 | 两处各存一份会让「界面里改了但命令行行为没变」无法归因 |
| 清单只有 PI 原生注入一处 | 有两个注入口就有两个「现在到底看得见哪些」，停用在其中一个里不生效 |
| 停用必须移动目录 | PI 没有 enabled 标志位，只改内存或 KV 是「界面显示已停用、模型照常看得见」的假状态 |
| 同名导入追加序号而不覆盖 | 覆盖会静默毁掉用户已经改好的技能 |
| 一个坏技能只跳过它自己 | 手写 frontmatter 出错是常态，不许让整个助手起不来 |
| 导入路径经 SafeJoin | zip 与目录导入都是外部输入，`..` 穿越会写出技能目录 |

## 取舍

不做技能市场、不做热插拔执行体。Skill 保持纯文本。
应用不预置任何技能：管理入口（新建 / 导入 / 启停 / 删除 / 预览）全部在设置页里能点完，
这是一条独立于模型的路径。

- **停用最彻底**：目录移出 PI 的扫描范围，对模型真正不存在；代价是移动会真报错
  （目标同名报 8111），而不是静默假成功
- **工作区技能界面不搬**：那是用户项目里的文件，停用入口仅对全局技能开放；
  代价是工作区技能要在项目里自己管
- **真身在共享目录而不是数据库**：命令行与界面看到同一批文件，启停状态没有
  第二份要同步——代价是所有操作都是真文件操作，失败会如实报错
