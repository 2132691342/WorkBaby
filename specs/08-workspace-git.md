# 08 · 工作区版本视图

## 定位

助手会在用户的文件夹里读写文件、跑脚本、改代码。**「它到底改了什么」必须能被看见**——
看不见就只剩下信任，而信任在第一次改坏文件之后就归零了。

这一块回答四个问题：改了哪些文件、每个文件改了什么、这个仓库发生过什么、
以及把眼前的改动收成一个提交。看的永远是助手实际干活的那个目录。

**读全开放，写受控**：状态、差异、历史、文件历史都是只读；
写入限 `stage` / `unstage` / `commit` / 新建分支 / 切分支 / `push` 六种，
且每一种都**由用户点下去**，助手不代提。

## 设计

| 决策 | 选择 | 为什么 | 代价 |
|---|---|---|---|
| 读写范围 | 读全开放；写限六种白名单动作 | 「准备一次提交」是办公闭环的一部分，但写版本历史不可逆 | 要维护白名单与一组确认态 |
| 命令白名单 | 显式列举允许的子命令与参数 | 字符串拼命令等于把 `--force` 一起放进来 | 加一种动作要改一处白名单 |
| 实现方式 | 调系统 `git` 命令 | 仓库状态与差异的语义由 Git 定义，自己解析 `.git` 等于重实现对象格式与索引 | 机器上得装 Git；每次读有进程开销（毫秒级，有超时兜底） |
| 提交信息 | 用户填；可让助手按 diff 起草 | 提交信息是这次改动的摘要，作者只能是用户 | 多一次模型调用与一条失败退路 |
| 依赖方向 | `backend/git` 是能力域；`service.GitService` 装配，`api` 只做参数与响应 | 与技能同一条链路，不新增一条旁路 | 多一层 service（但工作目录校验只该有一处） |
| 失败表达 | 没装 Git / 不是仓库 = **状态**不是错误 | 处置动作是「去装 / 去初始化」，报错只会让人反复点刷新 | 前端要判 `available` / `is_repo` 而不是只看 code |

`backend/git` 不依赖任何业务包（只引 `domain` 与 `pkg`），因此可以被单测直接驱动——
差异解析与写入护栏是这个包里最容易写错的两处，都必须有测试。

### 写入白名单

允许的动作及其参数：

| 动作 | 实际命令 | 约束 |
|---|---|---|
| 入栈 | `add -- <path>` | 路径必须落进工作目录；`--` 之后的路径不做通配展开 |
| 出栈 | `reset HEAD -- <path>` | 同上；只动索引，不动工作区文件 |
| 提交 | `commit -m <msg>` | 信息非空、≤ 5000 字符；不加 `--amend`、不加 `--no-verify` |
| 新建分支 | `checkout -b <name>` | 名字只允许 `[A-Za-z0-9._/-]`、≤ 128 字符、不以 `-` 开头 |
| 切分支 | `checkout <name>` | 名字同上；不带 `--force`、不带 `-f` |
| 推送 | `push` | 当前分支推当前上游；**禁止 `--force` / `--force-with-lease`** |

明确禁止（白名单之外一律拒绝，不解析、不猜测）：

| 禁止 | 原因 |
|---|---|
| `push --force` 及任何变体 | 覆盖远端历史，别人的提交会静默消失 |
| `reset --hard` | 静默毁掉工作区里未提交的改动 |
| `branch -D` / `-M`（强改） | 删未合入分支、改写分支指向 |
| `clean -fd` | 静默删除未跟踪文件 |
| `commit --amend` / `--no-verify` | 改写已发布历史、跳过钩子 |
| `checkout --force` / `-f` | 用索引覆盖工作区改动 |
| 任何 `-C <dir>` / `--git-dir` / `--work-tree` | 换目录等于绕过工作区校验 |

## 契约

| 方法 | 路径 | 出参 |
|---|---|---|
| GET | `/api/v1/git/status?session_id=` | `GitStatusVO`：`available` / `reason` / `is_repo` / `workspace` / `branch` / `ahead` / `behind` / `files[]` / `git` |
| GET | `/api/v1/git/diff?path=&session_id=` | `GitDiffVO`：`path` / `truncated` / `dropped` / `lines[]` |
| GET | `/api/v1/git/history?limit=&session_id=` | `GitHistoryVO`：`commits[]`（`hash` / `short` / `subject` / `author` / `when` / `files` / `additions` / `deletions`） |
| GET | `/api/v1/git/commit?hash=&session_id=` | `GitCommitVO`：元信息 + `files[]` + `lines[]`（复用差异行结构） |
| GET | `/api/v1/git/file-history?path=&limit=&session_id=` | `GitFileHistoryVO`：`commits[]`，按时间倒序 |
| GET | `/api/v1/git/branches?session_id=` | `GitBranchVO[]`：`name` / `current` / `ahead` / `behind` |
| POST | `/api/v1/git/stage` | `{session_id?, paths[]}` → `GitStatusVO`（写后重读，界面不必自己拼状态） |
| POST | `/api/v1/git/unstage` | `{session_id?, paths[]}` → `GitStatusVO` |
| POST | `/api/v1/git/commit` | `{session_id?, message}` → `GitStatusVO` + `hash` |
| POST | `/api/v1/git/branch` | `{session_id?, name}` → `GitStatusVO`（新建并切过去） |
| POST | `/api/v1/git/switch` | `{session_id?, name}` → `GitStatusVO` |
| POST | `/api/v1/git/push` | `{session_id?}` → `GitStatusVO` |
| POST | `/api/v1/git/message` | `{session_id?, paths[]?}` → `{message}`：助手按当前 diff 起草提交信息 |

`session_id` 决定看哪个目录：给了就看**该会话的工作目录**，没给（或会话已被删）退回全局工作目录。
只用全局会看错地方——会话级目录是这个会话里改动真正发生的地方。

所有写端点都返回**写后重读的 `GitStatusVO`**：让界面用一份数据刷新列表，
而不是前端自己推断「刚才入栈的那个文件现在应该长什么样」。

`files[]` 的 `status` 取 `M` 改过 / `A` 新增 / `D` 删除 / `R` 改名 / `?` 未跟踪；
`staged` 区分「已放进待提交区」与「只改了工作区」——两者是两种处置动作。
`lines[]` 的 `kind` 取 `file` 文件头 / `hunk` 段头 / `add` / `del` / `ctx`，
`old_no` / `new_no` 为 0 表示该侧没有对应行。

错误码：

| 码 | 含义 | 处置 |
|---|---|---|
| 1015 | 读不了版本信息（没装 Git / 执行失败 / 超时） | 装 Git / 重试 |
| 1016 | 提交信息为空或超长 | 补一句 / 缩短 |
| 1017 | 没有可提交的改动 | 先选文件入栈 |
| 1018 | 这个操作不被允许（命中禁止清单） | 用自己的 Git 工具做 |
| 1019 | 写操作执行失败（钩子拒绝 / 合并冲突 / 推送被拒） | 按 git 的原文提示处理 |

路径越界走既有的 `1004`，工作目录不存在 `1003`，文件不存在 `1005`。

## 关键流程

### 看改动

1. 前端进 `/workspace` → `GET /git/status`
2. 不可用（`available=false` 或 `is_repo=false`）→ 空态卡 + 一句可执行的下一步，不进列表
3. 可用 → 分支条 + 改动列表，同时拉「整个工作区」的差异（`path` 为空）
4. 点某一行 → `GET /git/diff?path=…`，行上转圈、右栏换成这份差异
5. 读失败 → toast 说清是哪个文件读不出来（列表那一行还亮着，不说就是「点了没反应」）

状态**不自动轮询**：仓库状态不会自己变，变的只有助手的行为；刷新是显式按钮。

### 提交

1. 用户在改动列表里勾选要入这次提交的文件 → `POST /git/stage`
2. 想省事：点「让助手起草」→ `POST /git/message`，信息框填入草稿（**可改，不自动提交**）
3. 确认框列出将入提交的文件与增删行数，用户点确认 → `POST /git/commit`
4. 成功 → 列表刷新（空改动）+ toast 带上提交号，点提交号跳到历史页那一条
5. 失败 → 原文提示（钩子拒绝 / 无改动 / 推送被拒），不猜原因

**提交前一定列出文件与增删行数**：用户看到的「提交」两个字背后是哪些文件，
必须在这一刻可见；看不见就会把不想提交的文件一起带进去。

### 看历史

1. 历史页 → `GET /git/history`，一页若干条，滚动加载更多
2. 点一条 → `GET /git/commit?hash=…`，抽屉里显示这次提交改了哪些文件与逐行差异
3. 在某个文件的差异上点「这个文件的历史」→ `GET /git/file-history?path=…`
4. 文件历史里点一条 → 同样打开该提交的差异抽屉

## 不变量

| 不变量 | 锁死原因 |
|---|---|
| 路径必须落进工作目录（`pkg.SafeJoin`） | 工作区之外的文件不该被这个入口读到，写入时更要命 |
| 折相对路径前两侧都先过 `pkg.RealPath` | 同一份路径的短名（`RUNNER~1`）与长名、符号链接形式字面不等，直接 `filepath.Rel` 会算出 `../..`，git 当场判「在工作区之外」 |
| 写命令走白名单，参数逐个校验 | 字符串拼命令会把 `--force` 一起放进来，而它的后果不可逆 |
| 提交信息非空且 ≤ 5000 字符 | 空信息让这次提交在历史里无法辨认 |
| 提交前必须可见将入的文件与增删行数 | 看不见就会把不想提交的文件带进去 |
| 差异有 3000 行 / 256KB 双上限，截断必须回报 `dropped` | 静默截断会让用户以为文件就这么长 |
| 未跟踪文件整篇按新增行读出 | `git diff` 对新文件给不出内容，「新建的文件」否则永远看不到 |
| `@@` 头给出的就是首行行号（先落号再推进） | 差一位就是整块行号整体偏移，对账对不上 |
| 命令带超时（status 10s / diff 15s / 写 30s / push 60s） | 大仓库不该把界面卡住；推送可能真的慢，给足 |
| 没装 Git 与「不是仓库」不返回错误 | 它们的处置动作是「去装 / 去初始化」，不是重试 |
| 写后一律重读状态返回 | 前端自己推断状态会出现「界面说已入栈、git 说没有」 |
| 助手只起草提交信息，不提交 | 提交是用户的决定；助手代提会让「这次改动是谁的意思」说不清 |

## 取舍

- **写限六种白名单动作**：换来「准备一次提交」在应用内闭环；
  代价是 `rebase` / `cherry-pick` / `stash` / `reset --soft` 这些仍然要回用户自己的 Git 工具，
  且每加一种动作都要过一遍「它能不能不可逆地毁东西」
- **提交信息可助手起草**：省掉想一句话的工夫，diff 就在手里；
  代价是多一次模型调用与一条失败退路（起草失败就手写，不许空着提交）
- **历史与文件历史是实时 `git log`**：不另建一张提交表；
  代价是深历史翻页有进程开销，且换分支后历史整块变（这正是不该缓存的原因）
- **走系统 Git**：零解析成本、语义永远与 Git 一致；
  代价是首屏要处理「没装 Git」这条分支
- **差异在后端折成行结构**：前端不必懂统一差异格式，两处配色规则也只在一处实现；
  代价是出参比原始文本大，且截断策略由后端决定（界面只能照实说）
