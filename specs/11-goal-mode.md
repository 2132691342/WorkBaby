# 11 · 目标模式

目标模式让长任务从「一次问答」变成「逐轮推进直到达成」：设定目标后，每轮 run 正常收尾时
用一次独立的小型 LLM 调用**按实据校验**是否达成；未达成则携带「下一步动作」自动续跑下一轮。

## 1. 目标模型

```go
type SessionGoal struct {
	Text        string // 目标描述（越具体、越可校验越好）
	Status      string // active / paused / done
	Round       int    // 已自动推进的轮数（含当前轮）
	MaxRounds   int    // 自动续跑轮数上限（防失控；0 = 默认 20）
	NextStep    string // 最近一次校验给出的下一步动作
	DoneBecause string // 判定达成时的依据摘要
	UpdatedAt   int64
}
```

存会话 `MetadataJSON` 的 `goal` 键（不为一个状态加列）。

### 操作（`/goal`）

| 动作 | 语义 |
|---|---|
| `set` / `replace` | 设定或替换目标；已有活动目标时保留轮次与上限 |
| `pause` | 暂停（已完成的轮次与产物都保留） |
| `resume` | 恢复（`done` 状态不可恢复，需设新目标） |
| `clear` | 清除 |

每次状态变化落库并广播 `chat:goal`（无 run 归属，按会话送达）。

## 2. 校验：只看实据

`goalVerdict` 是一次独立的 LLM 调用（短超时 60s、低温度、限 400 token），
输入是「目标 + 本轮最终回复 + 本轮工具调用次数」。

### 校验准则（rubric）

| # | 准则 | 说明 |
|---|---|---|
| 1 | 产物存在 | 声称生成/修改的文件必须确实出现或变更；声称运行的命令必须 exit code=0 且输出与声称一致 |
| 2 | 可核对 | 检查项有可观测的证据（文件存在 + 内容匹配 / 命令退出码 + 关键 stdout），口头总结不算 |
| 3 | 范围匹配 | 完成的是用户问的事，不是顺手的扩展或绕开 |
| 4 | 反例触发 | 出现「我已完成」「已经创建」「已经成功」一类无证据陈述 → `done=false` 且 `because` 写明 |

输出结构固定：

```json
{"done":false,"next_step":"","because":""}
```

`next_step` 必须具体可执行（像交给另一个工程师的任务卡）。

**为什么用 rubric**：避免「看起来完成了」的假达成——计划、待办清单、听起来像结论的回复都不算达成。

## 3. 续跑判定

`maybeContinueGoal` 在 run 成功收尾后调用：

| 情况 | 处理 |
|---|---|
| 无目标 / 非 `active` | 直接返回 |
| run 有错误（`res.Err != nil`） | 暂停目标（异常状态不盲目续跑烧 token） |
| 终止原因是 `cancelled` / `error` | 暂停目标 |
| 已达 `MaxRounds` | 暂停并提示「确认进度后可 `/goal resume` 继续」 |
| 校验调用失败 | 暂停并提示（校验失败按暂停处理——盲目续跑比停下来更糟） |
| 校验 `done=true` | 置 `done`，记录 `DoneBecause` |
| 校验 `done=false` | 记录 `NextStep`，**自动起新 run** 续跑 |

### 续跑消息结构

```
[目标续跑 · 第 N/M 轮] 当前目标：<Text>
上一步校验给出的下一步动作：<NextStep>
请直接执行该动作；目标完成后明确汇报达成的实据（改了哪些文件 / 跑了哪些验证 / 结果如何）。
```

续跑走正常发送链路（新 run，历史整体回灌）。

### 前端体验

`chat:done` 之后 SSE 连接**保持打开**：目标校验是一次 LLM 调用（可能数十秒），
保持连接才能无缝续看新 run 的事件。期间 `chat:goal` 也会继续送达。

## 4. 与其他机制的关系

| 机制 | 关系 |
|---|---|
| 反幻觉核验 | 独立的另一层：目标校验判定「是否达成」，反幻觉核验判定「声称的产物是否存在」 |
| 检查点续跑 | 互补：检查点处理「同一次 run 的中断恢复」，目标模式处理「跨 run 的持续推进」 |
| 后台任务 | 目标模式在前台会话推进；后台任务是提交即返回的独立作业 |

## 5. 取舍

| 取舍 | 优势 | 代价 |
|---|---|---|
| 独立 LLM 校验实据 | 避免假达成 | 每轮多一次模型调用（计入用量） |
| 校验带 rubric | 判定标准稳定，不随模型心情漂移 | prompt 较长（几百 token） |
| 异常收尾一律暂停 | 不在异常状态上继续烧 token | 用户需手动 `resume` |
| 轮数上限（默认 20） | 防失控 | 复杂目标可能需手动续 |
| 校验失败即暂停 | 失败不放大（不会带着错误判定续跑） | 上游抖动会中断目标推进（可 resume） |
| 目标状态存 `MetadataJSON` | 不加列、易扩展 | 无法用 SQL 直接查询目标 |
