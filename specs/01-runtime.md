# 01 · 运行时与路径

## 两个根，不要混

| 根 | 谁的数据 | 内容 |
|---|---|---|
| **Agent 目录** | PI | 会话、settings / models / mcp、技能、扩展、包 |
| **数据目录** | WorkBaby | 内置运行时、终端入口、SQLite（只有设置 KV）、日志、背景图、人设文件 |

Agent 目录按这个顺序解析：

1. `PI_CODING_AGENT_DIR` 环境变量（用户显式指定时绝不覆盖）；
2. `~/.pi/agent`。

**为什么不自己开一个目录**：那等于把用户的技能、插件、模型、会话全部隔离掉。
界面会显示「什么都没有」，而命令行里一切正常——两本账必然分叉。

## 工具链：一次解析，全局复用

`node` / `git` / npm 前缀由 `pi/env` 的**工具链解析**（`toolchain.go`）统一决定，
进程内只算一次，装 / 升 / 切之后作废重算。

| 组件 | 选择顺序 | 说明 |
|---|---|---|
| Node | 绑定的那份 → 系统（合规里版本最高）→ 内置 `runtime/node` | 系统 ≥ 22.19.0 就直接用，**一个字节都不解压**；一份能跑的都没有才解压内置 |
| Git | 系统（PATH → 注册表 → 常见安装目录）→ 已解压的内置 MinGit | 有系统 git 就绝不用内置那份；内置那份不在探测里解压 |
| npm | 与当前生效 node 同源 | 用户 node 合规就用它旁边的 `npm-cli.js`；没有才解压内置的 npm 脚本 |

**候选从哪来**（`nodeCandidates` / `gitCandidates`）：

1. 绑定记录里的那份；
2. `WORKBABY_NODE_EXE`（显式指定）；
3. **注册表里的当前 PATH**（系统级在前、用户级在后）——进程环境是启动那一刻的快照，
   用户装完 Node 没重启应用时它还是旧的，只看进程 PATH 会得出「没有 node」；
4. 常见安装根：`%ProgramFiles%\nodejs`、`%LOCALAPPDATA%\Programs\nodejs`、注册表
   `SOFTWARE\Node.js` 的 `InstallPath`、nvm-windows（`NVM_SYMLINK` + `NVM_HOME\v*`）、
   fnm（`%APPDATA%\fnm\node-versions\v*`）、scoop、winget；
5. 已解压的内置运行时。

**版本比较按完整版本号**：22.15 这类「看着够」的版本会一路 `EBADENGINE`，所以只认
≥ 22.19.0；合规候选有多份时取版本最高的那份（PATH 上先命中旧版也不将就）。

## 绑定：装引擎用的那份，后续只用那份

装 PI 时把 `node_exe` / `node_source` / `npm_script` / `pi_prefix` / `git_exe` 写进
`<data>/runtime/toolchain.json`。之后升级引擎、增删改插件、生成终端入口全部回到这份：

| 规则 | 原因 |
|---|---|
| 绑定那份还在且合规 → 优先用它 | 换了解释器或前缀就等于写出第二份 PI，机器上会出现两个 `pi` |
| 绑定那份失效（被删 / 低于下界）→ 重新解析并重新绑定 | 用户升级了 Node 或卸载了旧版本，不能一直卡在坏掉的那份上 |
| 显式切换（`POST /env/node`）→ 清掉旧前缀再绑定 | 旧前缀属于上一份 node 的生态，不能继续往那里写 |
| 绑定不写进 PI 的配置目录 | 它是 WorkBaby 的本地状态，不是 PI 的用户配置 |

## 内置运行时：只读现状，按需解压

归档随二进制 `go:embed`（`backend/runtime/bundled/`，Git LFS 托管）。探测（`InspectNode` /
`InspectGitBash`）只读版本标记与占位，**不解压**；解压只发生在真正要用它的时候：

| 时机 | 触发 |
|---|---|
| 内置 Node | 候选里一份能跑的 node 都没有 |
| 内置 Git Bash | 本机一份能跑的 bash 都没有（懒解压，给 PI 的 bash 工具兜底） |
| 内置 git.exe | 用户主动「启用内置 Git」（机器上一份 git 都没有时） |

Node 归档带顶层单目录，解压必须剥掉那一层——否则 `npm.cmd` 找错 node；MinGit 是平铺布局
不剥层，且它只带 `sh.exe`，解压后复制一份命名 `bash.exe`（同一二进制，按 argv[0] 回到正常
bash 模式），并在根下补 `tmp` 目录消掉 MSYS 启动告警。

## 提级与降级（PATH 落地）

三个组件各自可以挂在 **系统级 / 用户级 / 不挂** 三档，状态与动作都在「设置 · 运行时环境」：

| 组件 | 挂进 PATH 的目录 |
|---|---|
| `node` | 选中那份 node 所在目录（内置时是 `runtime/node`） |
| `git` | 选中那份 `git.exe` 所在目录（内置时是 `runtime/gitbash/cmd`） |
| `pi` | 终端入口目录 `<data>/bin` |

| 规则 | 原因 |
|---|---|
| 提级到系统级 = 追加 HKLM PATH 末尾 + 从用户级移除 | 系统级整段排在用户级之前，追加在末尾也已领先任何用户级条目 |
| 降回用户级 = 前置 HKCU PATH + 从系统级移除 | 用户级里前置才能压住其它用户级条目 |
| 只有「系统级写入或从系统级移除」需要 UAC | 纯用户级增删直接写 HKCU，不打扰用户 |
| 提级前查冲突：已经在用另一份同类运行时 → 拒绝（9725） | PATH 上多出一份 node / git 比没有更糟；系统里已有合规 node 时应改用系统那份，而不是把内置的提到它前面 |
| node 例外：那份同类运行时**不合规**（低于 22.19.0）时才允许提级 | 旧版本本来就不能跑 PI，提级是为了让终端也能用一份能跑的 |

写系统级经 ShellExecute `runas` 重跑本程序自己：`--path-admin <system|user|none> <dir;dir>`，
在单实例守卫之前拦截，改完注册表、广播 `WM_SETTINGCHANGE` 后即退出，结果只经退出码回传。
半途失败宁可留在 `both` 也不留在 `none`。用户在 UAC 点「否」是 9723，PATH 保持原样。

## PATH 注入

spawn PI 时只把**当前生效来源**的目录前置进 PATH（内置 node 生效才注入 NodeDir、
自装 PI 生效才注入安装前缀），并清掉继承来的 `npm_config_prefix`：

| 规则 | 原因 |
|---|---|
| 前置而不是追加 | 后置会被用户 PATH 上的旧版本抢先，选中的运行时等于没生效 |
| 只注入自装来源的目录 | 用户的 node / PI 生效时把我们数据目录里的旧副本也塞进去，反而会在 PI 的子进程里遮住用户正在用的工具 |
| 不覆盖 `PI_CODING_AGENT_DIR` | 换了它，用户已有的技能 / 插件 / 模型 / 会话全部看不见 |

## PI 的发现

```
WORKBABY_PI_EXE（显式/测试）
  → 用户 PATH 上的 pi.cmd / pi.exe / pi（本应用生成的终端转发目录要跳过）
  → 本应用自装前缀（runtime/npm-global）
  → 当前生效 node 的 npm 全局前缀
```

用户已有 PI 就用用户的，绝不另装一份；PATH 扫描按目录顺序进行（不是 LookPath 的
「第一个命中」——撞上自己的转发就拿不到后面的用户那份了）。

找到之后跑一次 `pi --version` 填进环境闸门；版本号只用于展示与排障。

找到的是 npm 的 shim（`pi.cmd` / `pi`）时，**起进程前先还原成 `node.exe` + 包内
`cli.js`**：经 `cmd.exe /c` 起进程每调一次闪一个控制台窗口，且
`CREATE_NO_WINDOW` 只作用于 cmd.exe 本身，它再拉起的 node 仍会带窗口。
`npm.cmd` 同理还原成 `npm-cli.js`。解析结果带缓存（shim 文本不会自己变）。

## 环境闸门

按 `node → pi → model` 的顺序报**首个**阻塞项，并给原因。`ready` 三者全满足才为真；
前端据此决定是否强制进向导——没有 PI 就没有对话，留一个空壳只会让用户以为程序坏了。

`model` 判定看的是 `models.json` 里是否有「至少一个带模型与密钥的服务」，
而不是 `settings.json` 有没有默认模型：PI 自己会在缺省时自动选第一个可用服务。

## 取舍

- **复用系统 Node / Git**：省一次解压、少动用户环境、与终端行为一致；代价是版本差异要靠闸门挡住（≥ 22.19.0 才放行）。
- **按需解压而不是启动即解压**：系统有合规 node 的机器上用户目录里不会多出 100MB；代价是首次真的缺运行时的那台机器要多等几秒。
- **绑定记录**：同一份 node 管到底，机器上不会出现第二份 PI；代价是用户手动换了 node 版本后，旧的那份若已删除要重新走一遍解析（自动完成，界面会提示原因）。
- **允许把内置运行时提到系统级**：没有 Node / Git 的机器也能在任意终端里用；代价是提级要过一次 UAC，且路径指向用户数据目录（换账户会失效）。
- **提级前查冲突**：不会把两份 node / git 同时塞进 PATH；代价是「系统里已有一份旧 node」时需要用户先升级或改用系统那份。
- **Git Bash 懒解压**：装了 Git 的机器不白占 200MB 磁盘；代价是没有 bash 的机器第一次修复要多等几秒解压。
- **不覆盖 agent 目录**：与 `pi` 共享一份状态；代价是卸载 WorkBaby 不会清掉 PI 的数据（这是对的）。
