# 使用指南

面向第一次打开 WorkBaby 的人：从配一个服务商到发出第一句话，再到把日常动作都用上。
本文只讲「怎么做、会看到什么」；为什么这样设计看 `docs/ARCHITECTURE.md`，
接口与字段看 `docs/API.md`，某条报错怎么处理看 `docs/TROUBLESHOOTING.md`。

界面只有四层：顶栏、左侧 rail（十个入口 + 底部的应用与设置）、当前区左栏、主区。
对话页多一根右侧工作台。下文按「第一次用」的顺序排。

---

## 1. 配一个服务商

服务商 = 一个兼容 OpenAI 接口的上游地址 + 密钥。入口是 rail 的「模型」（`/models`）。

1. 点「添加服务商」，填三项：
   - **名称**：自己认得的短名（如 `deepseek`）。它是内部主键；**编辑已有服务商时这一栏是禁用的**
     （`ProviderDialog.vue` 的 `nameLocked`），要换名字等于新建一个再删旧的。
   - **接口地址**：上游根地址，形如 `https://api.example.com/v1`。程序自己拼 `/chat/completions`（`backend/agent/provider_openai.go` 的 `Stream`），所以**不要**把 `/chat/completions` 写进去。
   - **API 协议**：下拉只有 `openai` / `anthropic` / `google` 三项（`frontend/src/views/ModelsView.vue` 的 `apiOptions`）。
   - **API Key**：粘贴原文。保存后界面只显示掩码（前 4 + `••••` + 后 4，`backend/service/models.go` 的 `maskKey`），原文再也不会回显。

2. 在弹窗里点「拉取模型」，程序会向上游要一次模型清单。成功与否是可见结果，不是异常：
   失败时回 `probe_ok:false` 加一句原因，而不是弹错误（`POST /providers/models`）。

3. 想手填也行：模型表里加行，至少填 `model_id`；`context_window`（上下文窗口）与 `max_tokens`（单次输出上限）
   填了才有意义 —— 窗口为 0 时上下文水位条不会出现（只显示读数，不显示占比）。

> 协议选 `anthropic` / `google` 能让「拉取模型」通过，但**聊天只有 OpenAI 兼容一条路**。
> 详见 `docs/PROVIDERS.md`；没把握就选 `openai`。

密钥的写入语义是「空串 = 保留原值」（`Upsert`，`backend/service/models.go`）。界面上留空再保存不会清掉已存的密钥；
要换就整条重填。

**读回来的一律是掩码**：服务商密钥在 `/providers` 里是 `api_key_masked`，
联网搜索密钥（`web.search_key`）在设置里是 `••••`。原文只有提交时那一瞬间在界面上；
掩码不可逆，所以别指望从界面把密钥抄回来。

---

## 2. 选一个模型

对话页输入框上方有模型选择器，模型来自所有服务商的扁平清单（`GET /models`）。
选中的是**当前会话的模型**，写在设置台账的 `model.active_provider` / `model.active_model`（`Chat.SetModel`）。

「新会话默认」是另一组键（`model.default_*`，模型页的「默认模型」卡）：
它只管**下一次开新会话**时用谁，不改正在进行的对话。默认三键可以不填。

**思考档**（`model.thinking_level`）四档出现在界面里：`off` / `low` / `medium` / `high`。
接口额外接受 `minimal`，但界面不提供。只有 `low` / `medium` / `high` 会真的发给上游
（`reasoning_effort` 字段，`backend/agent/provider_openai.go`）；`off` 与 `minimal` 不发，让上游用它自己的默认。

## 3. 选一个工作区（必须）

模型能碰的一切都在工作区内。没选工作区时对话、文件、git、索引全部回 `5000`「请先选择工作区」
（`Chat.BindSession` 第一行就判）。

三处入口任选：设置页的工作区面板、对话页输入框底栏的 `WorkspaceChip`、托盘菜单的「最近工作目录」。
切换工作区会：写 `workspace.current`、把路径顶进 `workspace.history`（最多 24 条）、
广播 `workspace:changed`、并**丢掉当前会话绑定**（`App.SetWorkspace` → `Chat.OnWorkspaceChanged`）。
正在跑的那一轮会被中止。

为什么必须：会话按工作区分子目录存放（`data\sessions\<编码后的路径>\`），工具的相对路径也相对它解析
（`Registry.resolve`），所以「没有工作区」就没有可读可写的地方。

第一次选之前可以先不管：首屏会照常画出来，只是聊天页显示「请先在设置里选择工作区」。

工作区这两个键是**保留键**：只有「切换工作区」这一个入口能写它们。
通用保存接口收到 `workspace.current` / `workspace.history` 会直接回 `1000` 拒掉 ——
工作区一改，绑定的会话、守卫路径、索引全得跟着走，绕开那个入口写它必然对不上。

## 4. 发出第一句话

在输入区打字，回车发送（`Enter` 发送、`Shift+Enter` 换行）。发送后有三种落法，接口用 `disposition` 表达
（`POST /chat/send` → `ChatSendREQ` 返回 `run_id, disposition`）：

| `disposition` | 含义 | 界面表现 |
|---|---|---|
| `started` | 引擎受理，起了一轮 | 开始流式输出 |
| `queued` | 引擎正忙，这句进了插话队 | 出现在队列条里 |
| `handled` | 这句话是斜杠命令，当场被消费，没有运行 | 不进入流式态 |

首句发出时会自动创建会话文件（`data\sessions\<工作区编码>\SES_<ULID>.jsonl`）并记住它
（`prefs.last_session_file`）。

### 流式过程中你会看到什么

- **思考折叠**：模型的思考过程单独成块，默认收起，点开看。流式期单块只保留尾部 8000 字
  （`maxLiveBlock`，`backend/service/chat_stream.go`）；落盘的历史是完整的。
- **工具卡片**：模型调工具时出现一张卡，含入参、输出、耗时、状态。改文件的工具额外带逐行差异；
  `edit` / `write` 会把 `diff` 与 `file_path` 写进结果（`backend/agent/tool_fs.go`）。
- **轮尾改动芯片**：这一轮改过哪些文件，点开在右侧工作台看完整文件或差异。
- **上下文水位**：输入区附近的读数。窗口来自模型的 `context_window`；模型没填窗口就只剩 token 读数。
- **用量带**：每轮结束显示这次的 token 组成。这几个数是**逐条消息累加**出来的真值 ——
  输入 / 输出 / 缓存读 / 缓存写四项分开统计（`backend/service/chat_state.go` 的 `usageSnapshot`）。
  服务商没回报用量的那一轮，这几项就是 0，不是「统计坏了」。
- **会话统计**（`/chat/state` 的 `stats`）：消息条数按角色数（用户 / 助手 / 工具），
  token 数按上面的口径累加；`total_messages` 是三者之和。

### 停止 / 插话 / 排队

| 动作 | 语义 | 后果 |
|---|---|---|
| 停止 | 中止本轮，**并作废两条排队** | 已经吐出的半截回复**会落盘**，标 `stop_reason="aborted"`（`persistPartial`），重开应用还在。排队里的话术**不会白丢**：接口把它们原样回给界面，界面据此放回输入框，你改一改还能再发 |
| 插话（`/chat/steer`） | 正在跑时再发一句 | 进插话队，本轮收尾前折进上下文；没有运行中回 `5003` |
| 排队（`/chat/followup`） | 本轮结束后另起一轮 | 进追加队；没有运行中回 `5003` |

停止时正在跑的子进程会**立刻被杀**（不等它自己超时），所以一条卡住的构建命令不会拖住下一轮。

清空队列与单条移除见输入区的队列条（`/chat/clear-queue`、`/chat/remove-queued`）。

一轮里最多 24 次「模型调用 → 工具执行」（`maxSteps`，`backend/agent/loop.go`）；用满会明确报错，不静默截断。

## 5. 计划模式

开关是输入区的按钮或 `/plan`。状态存进会话文件的 `custom` 条目（`customType="plan-mode"`），
所以切走再回来、重开应用都还在；新会话从关开始。

它的作用是**只读**：写工具能被声明，但执行会被拦下（`planDeniedResult`，`backend/agent/policy.go`）。
只读白名单是 `read` `grep` `find` `ls` `todo` `ask` `web_search` `web_fetch`；其余一律按「会改」处理 ——
包括 `index_search`（未登记，保守方向）与所有 MCP 工具。

被拦时模型收到一句「现在是计划模式，退出后（`/plan off`）再执行」，不是干巴巴的禁止。
界面横幅同一份状态，不会出现「横幅说只读、工具却在写」。

---

## 6. 提问卡

模型需要你选或填时才发卡（`ask` 工具），四种形态：确认（是/否）、单选（从选项挑一个）、
单行输入、多行编辑。卡片里回答后这一轮继续。

- 答完接着跑；取消则往会话里追加一条用户消息「（用户取消了那次提问）」（`appendAnswer`）。
- 卡片不会自动超时：`ask` 只等回答与中止（`ctx`）。
- 提问期间刷新界面，卡片**回不来**（`/chat/state` 不带待答清单）。
- 回答一条已经不在等待的提问不会丢：同样当普通用户消息追加进会话（`Answer` 走 `appendAnswer`）。

---

## 7. 待办面板

模型用 `todo` 工具维护一份清单，对话页底部栈实时显示（`chat:todos` 帧）。
清单的内容是「活动分支上最近一次 `todo` 调用的全量表」派生出来的，不是另一个存储
（`parser.TodosFromEntries`）。`status` 为空或为 `deleted` 的行不显示。

它只是给模型和你看的进度条，不影响工具能不能跑。

## 8. 会话

入口是 rail 的「会话」（`/sessions`）与对话页左栏，两处同一个列表组件。范围可切「当前目录 / 全部目录」。

| 动作 | 说明 | 注意 |
|---|---|---|
| 打开 | 点一行 | 有一轮正在跑时切到别的会话会回 `5002`；切到同一份则不拦 |
| 改名 | 行菜单 | 追加一条 `session_info` 条目，**不改写文件**；这份会话正被引擎打开时回 `5002` |
| 删除 | 行菜单，二次确认 | 删文件，同时清掉它的隐藏台账键；**正被引擎打开的会话不能删**（回 `5002`） |
| 隐藏一轮 | 轮菜单 | 只记在设置台账 `chat.hide:<会话路径>`，会话文件不动；隐藏的轮在回放里被剔除 |
| 取消隐藏 | 同上 | 同上 |
| 克隆 | 输入区斜杠命令 `/clone` | 只复制**消息**条目，不复制模型切换与用量；有新会话文件 |
| 分叉 | 从某条用户消息 | 复制到该条（含）为止；原会话一个字节不动；分叉点不在会话里回 `5003` |
| 导出 HTML | 斜杠命令 `exporthtml` | 自包含单文件，样式内联 |
| 导出 Markdown | 斜杠命令 `export` | **纯前端生成**，含全部历史轮次但只取文字块；思考块、工具输出、差异不导出 |

列表里的条数、token、费用、更新时间都是扫文件算出来的，不另存一份（`parser.Summarize`）；
所以删掉设置台账不会丢会话，但删掉 `data\sessions` 就真的没了 —— 会话就是历史本身，不可重建。

## 9. 技能

入口是 rail 的「技能」（`/skills`）。三区列表：启用区 `data\skills`、停用区 `data\skills_disabled`、
项目区 `<工作区>\.pi\skills`（只读）。

| 动作 | 实际做什么 |
|---|---|
| 安装 | 把 `assets\skills\<目录>` 复制进启用区；已存在则拒绝。只认推荐清单里的 10 个目录名 |
| 启用 / 停用 | **在两个区之间搬目录**。没有配置文件开关：目录在哪个区就是什么状态 |
| 新建 | 在启用区建 `<目录>\SKILL.md`，名字清洗成小写字母数字与短横线（中文保留，其余字符换成 `-`）；清洗后为空直接拒 |
| 导入 | 从外部目录复制（必须有 `SKILL.md`）；两区同名则拒绝；复制完源目录改删不影响副本 |
| 编辑 | 改 `SKILL.md` 正文，原子写 |
| 重置 | 从随包原件覆盖回原位，保持它此前在哪个区；只有内置技能能重置 |
| 删除 | 删整个技能目录。参数必须是 `SKILL.md` 路径，传目录路径一律拒 |

项目技能（`.pi\skills`）属于那个仓库：壳里既不能开关也不能删，只能读。它也**不进**模型的技能索引 ——
模型只看托管的启用区。

启用之后模型就看得见它了：

- 每轮开始前，程序重扫一次启用区，把「名字 — 一句话说明 — `SKILL.md` 绝对路径」列成系统提示里的
  一段「## 可用技能」索引。超过 40 条就按清单顺序截断。
- **索引里没有正文**：模型看到的是「这项技能是干什么的、在哪个文件」，任务对得上时它自己去
  `read` 那个路径的 `SKILL.md`，按里面的步骤做事。
- 技能正文在工作区之外（数据目录里），但 `read` 对已启用技能的 `SKILL.md` 放行；
  `write` / `edit` 对同一个文件一律拒绝 —— 技能有原件、副本、台账三份状态，
  改动只该走技能页。
- 索引是「本轮开跑那一刻」的快照：这轮跑到一半你切换了技能，要下一轮才生效。

技能的身份是**目录名**；显示名取 `SKILL.md` YAML 头的 `name`，没写就用目录名。
头的 `description` 是一句话说明，它就是模型用来判断「要不要读这条技能」的唯一依据，写清楚点；
`skill_requires` 来自推荐清单，不是从文件读的。

## 10. MCP

入口是 rail 的「MCP」（`/mcp`）。这里做两件不同的事，容易混：

- **登记**：写进 `mcp.json`（用户级 `data\mcp.json`，项目级 `<工作区>\.pi\mcp.json`），可开关、可测连接。
- **装载**：引擎只装载 **stdio** 型条目（有 `command` 的）。`url` 型条目能保存、能测连接，
  但**不会**变成模型能调的工具。

所以「保存成功」不等于「模型能用」。工具名是 `mcp_<服务名>_<工具名>`；
服务名只允许字母、数字、`_`、`-`，因为它要拼进工具名。

「测试连接」是真握手（stdio 拉进程走 `initialize` → `tools/list`；HTTP 发请求），
成功会告诉你看到了几个工具。条目停用时测试直接回「先启用再测」。

同名条目项目级覆盖用户级；删除只动界面上显示的那一条，另一层的同名条目不受影响。

改完配置后台会重建引擎的工具段，界面靠 `mcp:changed` 刷新。单个服务装载失败只记日志，其它服务照常。

## 11. 模板

设置页的「模板」面板。一份模板是 `data\templates\<name>.md`，YAML 头写 `name` / `description` / `args`，
闭合 `---` 之后全是正文。

名字会是文件名，所以只允许小写字母、数字、连字符。头里的值会被压成一行（YAML 头的标量不能带换行）。

**保存时名字会被清洗**，落盘用的是清洗后的那个（`My Template` → `mytemplate`：转小写、
非法字符直接丢掉、首尾的 `-` 去掉）。界面必须拿保存接口回的那个名字去删除 ——
拿原文去删会找不到刚存下的那一份。
清洗后为空（全是非法字符）直接回 `1000`，不落盘。

模板出现在斜杠菜单里（来源标 `prompt`），选中后**把正文填进输入框**，不直接发送 ——
正文通常带占位参数（如 `<文件> <风格>`），要你补完再发。

名字与内置命令冲突时（例如你建了一份叫 `new` 的模板），内置命令优先。

## 12. `@` 引用

输入区打 `@` 打开引用浏览器，两类目标：

- **工作区文件**：点目录逐级进入，或在过滤框里搜文件名（服务端只按文件名匹配）。
  选中后变成一个文件附件：正文里追加 `[附件] <绝对路径>`，让模型自己按需 `read`（`compose`，`backend/service/chat_actions.go`）。
- **最近会话**：列表底部列出最近几条会话，条数由设置 `ui.mention_sessions` 控制（1~20，默认 5，
  浏览器里就地 +/− 即可改）。选中后把那段会话的正文**整段折进消息** ——
  会话文件在工作区外，模型的读文件工具读不到它。

附件另有两条来源：粘贴图片、回形针选文件。图片走内容块（唯一的二进制通道），文件走路径引用。

带附件时**不认斜杠命令**：这条消息一定发给模型。

## 13. `/` 命令

命令清单来自后端（`ChatStateRESP.commands[]`，`command_source` 为 `builtin` 或 `prompt`），
前端再并进自己的一组界面命令。菜单合并时**内置的与引擎同名的只留内置**（`useComposerMenu.ts` 的 `builtinKeys`），
避免同一个动作出现两次。

真正的分流发生在发送那一刻：消息不带附件、且以 `/` 开头时，后端先试 `HandleCommand`
（只认 `/new` `/compact` `/plan`，`backend/service/chat_state.go`）。认得就当场消费并回 `disposition:"handled"`，
不登记运行；不认得就原样发给模型。所以前端那组命令是**在选中菜单项时就执行完**的，不经过发送路径。

**后端声明并由发送路径消费**（`nativeCommands`，`HandleCommand` 只处理前三条）

| 命令 | 做什么 |
|---|---|
| `/new` | 开一份新会话。有运行在跑回 `5002` |
| `/compact [指示]` | 手动压缩上下文。同步调上游做总结（120s 上限），有运行在跑回 `5002` |
| `/plan [on\|off]` | 开关计划模式；不带参数按当前状态取反 |
| `/export` | 只做声明；菜单里被前端同名的 `export` 顶掉（见下） |

**前端执行**（选中菜单项即执行，不经过发送路径；`useBuiltinCommands.ts`）

| 命令 | 做什么 |
|---|---|
| `/new` | 调 `POST /chat/new` 开新会话（与后端那条同名，菜单里只留这一份） |
| `/model` | 打开模型选择器（不弹新层，直接叫输入框底栏那个） |
| `/thinking` | 打开思考档选择器 |
| `/compact` | 调 `POST /chat/compact` |
| `/copy` | 复制最后一条助手回复的正文 |
| `/export` | 导出 Markdown（纯前端，见 §8） |
| `/exporthtml` | 调 `POST /chat/export-html` 导出 HTML |
| `/reload` | 重新探测外部工具、重拉会话清单与模型清单，再刷当前会话 |
| `/clone` | 调 `POST /chat/clone` 克隆当前会话 |

因为菜单按 `BuiltinKey` 去重，实际能点到的是这 9 条：`new` `model` `thinking` `compact` `copy`
`export` `exporthtml` `reload` `clone`。

`exporthtml` 与 `clone` 按引擎能力位过滤（`export_html` / `session_clone`）；不满足就不进菜单，不显示灰项。

模板命令与上面并进同一份菜单，来源是 `prompt`，选中只填正文。

## 15. 数据在哪

全部在 `%LOCALAPPDATA%\WorkBaby`（开发态是 `WorkBaby-dev`，两套完全隔离）。设置页的「启动行为」面板显示这个路径，
旁边的按钮直接打开目录（`POST /prefs/data-dir`）；「诊断」面板能看最近的失败现场与日志尾部。

| 内容 | 说明 |
|---|---|
| `workbaby.json` | 设置台账：外观、偏好、隐藏轮、模型指针 |
| `workbaby.db` | 服务商与模型（**含 API 密钥原文**）、检索索引 |
| `mcp.json` | 用户级 MCP 清单 |
| `sessions\` | 会话 JSONL，按工作区分子目录。删了就没有了 |
| `skills\` `skills_disabled\` | 启用 / 停用技能区 |
| `templates\` | 提示词模板 |
| `logs\` | 按天日志 `wb-YYYY-MM-DD.log` |
| `webview\` | WebView2 用户数据 |

`workbaby.json` 坏了不会卡启动：会被挪成 `workbaby.json.bad-<毫秒时间戳>` 再从空白开始（`repo.Open`）。
代价是设置与隐藏轮记录没了 —— 技能开关不受影响，它的真相在目录里。

**删 `workbaby.db` 等于删掉全部服务商密钥**，需要重填。它不是可以随便重建的缓存。

## 16. 卸载

卸载器会先问一句「同时删除用户数据吗」，默认**保留** `%LOCALAPPDATA%\WorkBaby`，
所以重装后会话、技能、设置都还在。选「是」才整份删掉。

`webview\` 目录无论选哪个都会被清掉（WebView2 缓存，没有保留价值）。

想彻底重来：先卸载（选删数据），或手动删 `%LOCALAPPDATA%\WorkBaby` 整个目录。
开发态对应 `WorkBaby-dev`，删掉它等于恢复出厂，不影响安装态。
