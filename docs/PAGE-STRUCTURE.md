# 页面结构

六个路由 + 未知路径兜底回首页；Frameless 窗口自绘顶栏 + 一级 rail + 当前区左栏 + 主区。

设计对象是「第一次用 AI 的办公人员」：任何需要解释的控件都不许出现。

## 路由

| 路径 | 视图 | 说明 |
|---|---|---|
| `/` | `views/ChatView.vue` | 对话主界面；`/?session={id}` 打开任意会话，消费后清掉参数 |
| `/setup` | `views/SetupView.vue` | 环境向导：运行时 / PI / 模型。`pi_env.ready=false` 时强制进这里 |
| `/workspace` | `views/WorkspaceView.vue` | 工作区：改动 / 提交 / 历史 / 分支四个页签（specs/08） |
| `/dashboard` | `views/DashboardView.vue` | 仪表盘：token 与花费 |
| `/help/:name?` | `views/HelpView.vue` | 帮助文档（内置只读手册） |
| `/settings/:tab?` | `views/SettingsView.vue` | 设置（七项，tab 落在 URL 上） |

**没有「指挥台」这类自造总览页**：「看见并控制」的落地点是对话页（工具卡 + 提问卡）、
工作区页（改动对账）与仪表盘（用量）——每个页面回答一个真问题，不为「看起来全」而加页。

- **顶栏**（`layout/TitleBar.vue`）：品牌瓦片 + 当前区标题（会话页显示会话名）
  + 折叠钮（仅对话页）+ 连接灯（已连接 / 正在重连 / 未连接）+ 窗控。不放导航
- **一级 rail**（`layout/NavRail.vue`，62px）：对话 / 工作区 / 技能 / 用量
  竖排在上，帮助 / 设置压在底部——一级导航只有这一处，设置是其中的一等入口。

  2px 主色竖条。「技能」直达 `/settings/skills`：它是高频目的，值得一级位

### 会话从哪来
会话列表读的是 **PI 的会话目录**（`~/.pi/agent/sessions/--<cwd>--/*.jsonl`）：

- 你在终端里用 `pi` 聊过的会话，这里同样看得到，点开就能接着聊
- 标题取 `session_info` 的名字或首条用户消息；右侧是相对时间（今天给时刻、一周内给天数、更早给日期）
- 行悬停让位给三个动作：重命名 / 导出 HTML / 删除
- 搜索框按标题过滤；分页默认 10 条，「更多」每次追加 20 条

**「新对话」不建空会话**：PI 要等第一条消息才落盘，所以点新对话只是把界面切到草稿态；
第一次发送时由后端现场创建，返回体里带回真正建出来的 `session_id`。

**一个工作目录只有一个进程、一个当前会话**：同一目录下第二条对话要等第一条跑完（5005），
不同目录各自一个进程，互不影响。

### 流式呈现

| 状态 | 呈现 |
|---|---|
| 思考中 | 呼吸点 + 「正在思考」+ 字数；只渲染尾部 4000 字 |
| 工具执行中 | 工具卡状态灯呼吸，展开看参数与输出（edit 的输出按 diff 着色） |
| 正文流式 | 正文末尾常驻闪烁光标；渲染节流 120ms（超 2 万字降到 280ms），渲染走块级增量缓存（DESIGN.md「消息流的视觉语言」） |
| 自动重试中 | 流末一条淡黄提示 + 「停止重试」按钮 |
| 输出被截断 | 一条警告 + 「继续」按钮 |
| 引擎提问 | 流末尾一张提问卡：确认 / 单选 / 填空 / 多行填空，拒绝永远安全；多选与自定义答案是扩展用这四种基元拼出来的（见 specs/10） |
| 运行读数 | 耗时 + 实时上下文 token，常驻在底部状态条（StatusHud），跑多久看得见 |

引擎提问（`chat:ask`）来自 PI 进程里的扩展，不挂在某一条消息上，因此统一排在流末尾；
回答走 `POST /chat/answer`，回给发出请求的那个进程。

### 回合分组

一条消息 = **角色徽章胶囊 + 内容容器**：徽章交代说话权属（用户右对齐染淡靛，
助手中性 + 呼吸点表示正在生成），助手正文是独立面板、左侧 2px 脊线是「助手列」
的身份线。一次「提问 → 回答」仍是**一整块**：助手那一列靠一条竖线（顶端一个节点）
串起思考、工具卡、正文。回合内 12px 间距，回合间 24px——靠紧才看得出是同一次动作。

### 输入区

三层结构：容器（composer）→ 输入块 → 工具行，层与层用分隔线切开——输入框是
「可以写字的面板」（min-height 68px，空态也有大目标），工具按钮不再抢它的横向空间。

- 流式期间输入框变「插话」模式：发送 = 插话（PI 的 `steer`），Esc = 停止（输入框为空时）
- 「排队」模式 = `follow_up`：等当前批次处理完再进；排队条实时显示后端的队列
- `@` 唤起工作区文件面板（逐级浏览 + 过滤 + 「浏览整个电脑」），`/` 唤起命令菜单：
  内置命令 + **PI 报上来的斜杠命令**（扩展命令与提示模板）+ 已启用技能
- 工具行：附件 · 工作区 chip · 模型 chip（左列服务商、右列模型；有会话时写回这条会话，
  新对话时写 PI 的默认模型）· 思考档 chip · 上下文水位环 · 插话/排队分段 · 发送 / 停止
- 底部状态条（`chat/StatusHud.vue`）：`服务商/模型 · 思考档 · 耗时 · 上下文 %/窗口`
  常驻可见；上下文 ≥70% 转琥珀、≥90% 转红
- 支持粘贴截图（进附件列表）、多选附件（最多 5 个，越界的标红说明读不到）
- 草稿按会话存 localStorage，切会话不丢

### 欢迎页

空态是唯一允许装饰性光晕的地方。内容：品牌徽章 → 标题 → 一句说明 → 例句卡（四张，
点一下直接发）或**配置引导卡**（`model_ready=false` 时优先显示）→ 脚注。

## SetupView（环境向导）

`pi_env.ready=false` 时强制进这里。三步，按 `blocking` 直接落到卡住的那一步。
与对话页不同，它是居中单列（720px 上限）的引导流，不占页头。

| 步骤 | 内容 | 失败时 |
|---|---|---|
| ① 运行时 | 系统已有 Node 22+ 就直接用；没有则用内置运行时 | 显示解压失败原因与 7002 / 7004 的处置动作 |
| ② 助手 | 显示探测到的 `pi_path` 与版本；没装则一个「安装」按钮，下方流式打印 npm 输出 | npm 原始输出尾部 + 「重试」 |
| ③ 模型 | 复用设置页的 Provider 面板 | 「至少配一个服务」的提示，不允许跳过 |

三项全绿才放行到对话页。rail 仍然在——用户能从向导直接跳出去看别的区。

## DashboardView

| 区域 | 内容 |
|---|---|
| 页头动作 | 7 / 14 / 30 天分段 + 手动刷新 |
| 读数卡 ×4 | 总 token / 输入-输出 / 缓存命中率 / 花费（每张带水印图标与一行注解） |
| 趋势图 | 按天输入与输出双面积线（ECharts，渐变取 `--wb-area-*`） |
| 按模型 | 占比环 + 图例列表（最多五段，其余归「其他」） |
| 会话榜 | 用量最高的 6 个会话，点一行直达 |

数据全部来自 PI 的会话文件（每条助手消息带 usage），没有用量时整页停在空态，不画空图表。

## WorkspaceView

助手干完活之后「它到底动了什么」要有地方对账；改动也能在这一页收成一次提交。
页签四个：**改动 / 提交 / 历史 / 分支**。

- 看的是**当前会话的工作目录**（切会话即重载）
- 写入只开放受控六动作（stage / unstage / commit / 新建分支 / 切分支 / push），
  提交这一下永远由用户点下去；禁止清单见 specs/08
- 变更列表 + 差异视图并排；历史与分支各自独立面板，提交详情与文件历史走抽屉
- 没装 Git 或不是仓库时给空态 + 一句可执行的下一步

## SettingsView

rail 的「设置」落在 `/settings`，左栏三组七项是**二级目录**（188px 窄档），
URL 是唯一真相（`/settings/:tab?`），主区带页头显示当前板块的标题与说明。

| 组 | 板块 | 要点 |
|---|---|---|
| 模型 | 模型服务 | 读写 PI 的 `models.json`：服务商卡片 + 编辑弹窗（接口类型 / 地址 / 密钥 / 模型行）；测试连通、显示密钥、设默认、从上游拉模型 |
| 模型 | 工具 | PI 此刻能调到的工具（内置 / 插件 / MCP），来源筛选 + 分页（默认 10 行，5/10/20/50 可选），开关写 `defaultTools` |
| 模型 | MCP | 服务卡片（名称 + 在线状态 + 传输地址行 + 工具数 + 登录）+ 配置原文编辑（全局 / 项目两份）+ 重连 |
| 能力 | 技能 | 来源筛选（我的技能 / 工作区 / 插件包）+ 分页（默认 10 行，5/10/20/50 可选）；开关 = 移目录；展开看正文；导入；删除 |
| 能力 | 插件 | 包（`pi install/remove`，输出流式打到面板）+ 扩展（目录 + 登记表启停、导入、删除、重载） |
| 界面 | 外观 | 主题两套、语言两套、界面字体五选一、字号四档、思考过程开关、自定义背景 |
| 界面 | 行为 | 工作目录、回车发送、关闭到托盘、开机自启、默认思考档、压缩参数、**页底列出 PI 的全部配置路径**（点一下复制） |

两个面板都是**表单式排版**：每组设置一个分节（图标 + 标题 + 分隔线），
行内标签定宽在左、控件紧随其后、控件只占一列；改完即存（写入 settings KV 与 PI 的
`settings.json`），没有「保存」按钮——它离字段太远时用户不知道自己在保存什么。

**外观与行为必须分开**：用户找设置时是带着目的来的——「别老弹窗确认」和「把界面调暗」是两件不相干的事。

七个面板用 `v-if` 懒挂载：只打开「外观」时不去拉模型服务与技能列表。

## HelpView

内置用户手册：二级目录（188px 窄档，可搜索）+ 主区 Markdown 阅读（带页头），
URL 是唯一真相（`/help/:name`）。
文档围绕「用界面操作 PI」写：快速上手 / 模型服务 / 技能与插件 / 工具与 MCP / 用量与花费 / 常见问题。

## 图标纪律

全站只有一种图标语言：`AppIcon.vue` 里的内联 SVG（24 网格、1.7 描边，深色主题 1.85）。
**禁止**用 Unicode 字符或 Emoji 冒充图标。
