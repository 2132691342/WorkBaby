# 页面结构

两个路由，侧栏 + 主区的桌面布局；Frameless 窗口自绘标题栏。
设计对象是「第一次用 AI 的办公人员」：任何需要解释的控件都不许出现。

## 路由

| 路径 | 视图 | 说明 |
|---|---|---|
| `/` | `views/ChatView.vue` | 对话主界面 |
| `/dashboard` | `views/DashboardView.vue` | 仪表盘：token 用量 |
| `/settings/:tab?` | `views/SettingsView.vue` | 设置（六个板块，tab 落在 URL 上） |

## ChatView

```
┌──────────────────────────────────────────────┐
│ titlebar：WB · WorkBaby · 状态灯 · 最小/最大/关闭 │
├────────────┬─────────────────────────────────┤
│ 新对话      │ chat-head：会话标题               │
│ 会话列表    │─────────────────────────────────│
│ （今天/本周 │ MessageList                      │
│  /更早）    │   turn = 用户气泡 / 助手回答        │
│            │   + 工具执行卡 / 思考 / 流式         │
│ 仪表盘      │   + 审批决策卡（紧跟触发它的回合）   │
│ 工具        │─────────────────────────────────│
│ 设置        │ ChatInput                        │
│            │   ┌ 上下文水位条（极细，低透明度）    │
│            │   ├ 待发送附件 chip 列表            │
│            │   ├ 多行输入 / @ 引用 / 斜杠命令     │
│            │   └ 模型 chip · 规矩 chip · 发送/停止 │
└────────────┴─────────────────────────────────┘
```

- 无消息时显示欢迎区 + 四张例句卡（点击直接发送）
- 流式期间输入框变「插话」模式，可随时打断
- 消息列与输入框共用同一个 `max-width`，左右边缘对齐
- 标题栏右侧一枚连接状态灯：SSE 断开时转黄，不弹提示不打断
- **模型与执行方式两个切换入口在输入框内**，不在 chat-head——
  「用什么模型」「要不要先问我」都属于这一轮发送的上下文
- `@` 唤起文件选择，`/` 唤起命令菜单
- `chat:done` 后拉取会话权威快照，前端不做增量合并

### 流式呈现

流式输出是这个产品的主交互，三种状态必须一眼分得清：

| 状态 | 呈现 |
|---|---|
| 思考中 | 左侧竖线 + 「正在思考」+ 字数，正文滚动跟随 |
| 工具执行中 | 工具卡状态灯转圈，展开看参数与输出 |
| 正文流式 | 正文末尾常驻光标（`::after` 闪烁），「还在写」不需要解释 |

三者的先后顺序固定：思考 → 工具 → 正文。思考块在流式期间默认展开，
跑完随消息一起折起——推理过程默认可见，但不该在事后长期占屏。

### 回合分组

一次「提问 → 回答」是**一整块**，不是几条消息。数据层一次回答会落成多条
`assistant`（中间夹着工具结果），`turnBlocks` 按 user 消息把它们收成一个回合：
**一个头像 + 一根不断的竖轨**，思考、工具卡、审批卡、正文、消息操作全挂在这根线上。

| 归属 | 规则 |
|---|---|
| 回合内 | 8px 间距，靠紧才看得出是同一个动作 |
| 回合间 | 24px 间距，靠松才看得出换了一次动作 |
| 审批卡 | 收进触发它的那一段 `.turn-tools`，与工具卡同列同缩进 |
| 找不到触发点的审批 | 仍走 `.turn-appr`：吃竖轨与助手列缩进，不退回容器左边缘 |

最后一条是硬约束：审批卡一旦贴到容器左边缘，竖轨在它上方断掉，
它就成了不属于任何一回合的悬空元素——而它恰恰是这一回合里唯一需要用户拍板的一步。

## SettingsView

六个板块，URL 是唯一真相（`/settings/:tab?`），刷新与前进后退都停在原处。

| 板块 | 组件 | 要点 |
|---|---|---|
| 模型服务 | `ProviderPanel.vue` | 六个预设模板一键填；模型走下拉拉取，不手打；测试连通；设默认 |
| 技能 | `SkillPanel.vue` | 开关启停（落库）；展开看正文；显示来源 |
| 知识库 | `KnowledgePanel.vue` | 多选文件导入；状态与分块数；就地检索 |
| 工具 | `ToolPanel.vue` | 按分类列出全部内置工具：用途、风险、是否要先问、参数；可逐个停用 |
| 外观 | `AppearancePanel.vue` | 主题两套；字体五选一；字号四档；思考过程开关 |
| 行为 | `BehaviorPanel.vue` | 执行方式三档；工作目录；托盘驻留与开机自启；回车发送；模型能力与窗口手填；Python 状态；关于 |

**外观与行为必须分开**：用户找设置时是带着目的来的——「我想让它别老弹窗确认」和
「我想把界面调暗」是两件不相干的事，挤在一屏里只会互相干扰。侧栏的「工具」入口
直达工具面板，因为「助手能干什么」是使用中随时会问的问题，不该藏在设置深处。

六个面板用 `v-if` 懒挂载：只打开「外观」时不去拉模型服务和技能列表。

## 设置项

| 键 | 取值 | 归属 |
|---|---|---|
| `theme` | `light` / `dark` | 外观 |
| `font_family` | `system` / `song` / `kai` / `hei` / `fang` | 外观 |
| `font_size` | `sm` / `md` / `lg` / `xl` | 外观 |
| `show_thinking` | `true` / `false` | 外观 |
| `permission` | `ask` / `auto_edit` / `yolo` | 行为 |
| `minimize_to_tray` | `true` / `false` | 行为 |
| `launch_on_login` | `true` / `false` | 行为（同步写注册表） |
| `send_on_enter` | `true` / `false` | 行为 |
| `workspace` | 绝对路径 | 行为 |
| `context_window` | 整数 | 行为（手填覆盖内置目录） |
| `context_reserve_tokens` | 整数 | 行为 |
| `disabled_tools` | 逗号分隔 | 工具面板写入 |

## 图标纪律

全站只有一种图标语言：`AppIcon.vue` 里的内联 SVG，24 网格、1.7 描边（暗色主题 1.85）。
**禁止**用 Unicode 字符（`+` `⚙` `✎` `×` `▸` `…`）或 Emoji 冒充图标——
它们在不同 Windows 缩放比例与字体下会变形，且没有统一基线。
