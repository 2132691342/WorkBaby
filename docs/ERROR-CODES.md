# 错误码

`AppError` 的 `code` 是对外契约的一部分：前端按它分流，用户按它判断「该重试、该改配置、还是该换做法」。
所以码值**只增不改**——改一个已有码的语义等于破坏所有依赖它的判断。

承载类型是**数字字符串**（`"1001"`），不是 int：响应信封 `{code, message, data}` 里的 `code` 是 `string`，
与 HTTP 状态码的 int 从类型上分开，前端写 `e.code === "5005"` 就不会有歧义。

- `message` 是给用户看的一句话：不出现字段名、堆栈、上游原文
- `details` 是补充定位信息，可为空，界面上收在错误条的展开里
- `"9999"` 是「这不是 AppError」的兜底码：任何裸 error 走到出口都归到它

段位归属表在 `AGENTS.md §2.4`。**当前在用的有八段**：

| 段位 | 域 |
|---|---|
| 1000–1999 | 通用 / 文件 / 路径 |
| 2000–2999 | 配置 / 持久化 / DB / SSE / 单实例 |
| 3000–3999 | 模型服务 |
| 5000–5999 | 会话运行（忙 / 插话队列 / 收尾 / 引擎提问） |
| 7000–7999 | 内置运行时 |
| 8000–8999 | 技能 |
| 9100–9199 | MCP |
| 9700–9799 | PI 子进程 / 协议 / 环境引导 |

4000 / 6000 / 9200–9699 三个段位随一批已退役模块一起停用：这些码不再产生，文档里也不再保留。

## 前端已落地的码级分流

| 码 | 前端动作 |
|---|---|
| 3101 | 错误条上给「去设置」按钮——重试解决不了的配置问题，不给入口就是让用户干瞪眼 |
| 5005 | 「同一个文件夹里还有对话在跑」：等它停下再操作，不给「强行切换」按钮 |
| 5010 | 摘掉那张已经失效的提问卡（等待超时 / 会话中止） |
| 1101 | 会话不存在：列表里已经没有它了，回首页 |

环境类问题（`9704` / `9709` / `9711`）不走码分流：前端在 `bootstrap` 里读环境闸门，
`ready=false` 就整屏进向导，轮不到这些码露面。它们出现在错误条里只有一种情况——
闸门判定之后环境又坏了（Node 被删、PI 被卸载），此时按通用错误条显示。

其余码走通用错误条：显示 `message`，需要时展开 `details`。

## 一个码承载多种语义的情形

同一码下并列多条含义是有意为之，前提是**用户的处置动作一致**：
例如 `1005` 同时覆盖「读文件失败」与「文件不存在」，两者的处置都是「确认文件还在」。

## 维护方式

码表与代码同源，改动时两处一起动：

```bash
# 代码里现在真正会产生的码
rg -o '"[0-9]{4}"' backend --glob '!*_test.go' | sort -u
# 对照本文件的码表，缺的就是漏写、多出来的就是已退役
```
