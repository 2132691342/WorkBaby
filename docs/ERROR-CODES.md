# 错误码

`AppError` 的 `code` 是对外契约的一部分：前端按它分流，用户按它判断「该重试、该改配置、还是该换做法」。
因此码值**只增不改**——改一个已有码的语义等于破坏所有依赖它的判断。

`message` 是给用户看的一句话（不出现字段名、堆栈、上游原文）；`details` 是补充定位信息，可为空。

## 段位

段位划分与 `AGENTS.md §2.4` 一致，新增码时按归属挑段位，不要跨段复用。

|---|---|---|
| 1000–1999 | 通用 / 文件 / 路径 / 会话 | `backend/pkg`、`backend/tool/files.go`、`backend/service/session.go` |
| 2000–2999 | 配置 / 持久化 / 启动装配 | `backend/config`、`backend/db`、`backend/server`、`backend/singleinstance` |
| 3000–3999 | LLM / Provider | `backend/llm`、`backend/service/provider.go` |
| 4000–4999 | 工具 / 审批 | `backend/tool`、`backend/service/approval.go` |
| 5000–5999 | Agent 内核 | `backend/agent` |

## 一个码承载多种语义的情形

同一码下并列多条含义是有意为之，前提是**用户的处置动作一致**：

- `1005` 同时表示「文件不存在」与「读取失败」——两者都只能让用户去看路径或权限
- `2001` 表示启动装配缺件（配置 / 工具注册表 / 事件出口 / 数据仓储未就绪）——都属于「程序没装好」，不该出现在运行期
- `2304` 覆盖开机自启的全部失败面——处置动作都是「去系统里手工设置」
- `3103` / `3111` 把「服务连不上」与「参数没给」分开，因为它们的前端引导完全不同

反之，**处置动作不同就必须分码**：`1009`（写前必读）与 `1010`（edit 未命中共 2 种）分开，
是为了让前端能分别提示「先读一遍」和「内容对不上」。
