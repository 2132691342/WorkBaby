# 排障

症状 → 原因 → 下一步。先看第一节的业务码，再看第二节的具体症状。
日志按天滚动在 `%LOCALAPPDATA%\WorkBaby\logs\wb-YYYY-MM-DD.log`（开发态 `WorkBaby-dev`），
界面里用设置页的诊断面板或 `GET /logs?lines=` 看尾部。发布版没有控制台，日志是唯一留痕。

---

## 1. 业务码

信封恒 HTTP 200，`code` 为数字字符串，`"0"` 是成功。**唯一不带信封的失败是鉴权 401。**
前端另有一个本地码 `8003`（连不上后端），后端不产生它。

| 码 | 含义 | 你会看到 | 下一步 |
|---|---|---|---|
| `1000` | 入参不合法 | 「请求体不合法」/「不能为空」/「未知的 X」 | 是调用方的问题：body 不是合法 JSON，或必填字段为空，或枚举不认识。看 `message` 指了哪个字段 |
| `1001` | 文件或目录不存在 | 「工作区不存在或不是目录」/「路径不存在」 | 选一个存在的目录；或目标已被删。重新选工作区 |
| `1002` | 路径越界 | 「路径不在工作区内」/「不允许访问内网地址」 | 同码两义：文件接口是「不在工作区根内」，联网是「目标是环回/私网」。前者改用工作区内的路径；后者是刻意的出口限制 |
| `1003` | 文件读写失败 | 「写入失败」/「目录不可写」/「超过 5MB」 | 磁盘满、权限不足、目标被占用，或文件超过写上限（5 MB，`service/files.go`）。退出占用程序或换位置 |
| `1100` | git 不可用 | 状态面板显示不可用原因 | 装 git 并确保在 PATH。不装只影响版本控制，不影响对话与工具 |
| `1101` | git 命令失败 | `detail` 是 git 的 stderr | 读 `detail` 原文。先看 `repo_state` 是否处于 merge/rebase；冲突不是错误，是待解决状态 |
| `1102` | 凭证被拒 / 无法输入 | 「需要登录」类提示 | 子进程带 `GIT_TERMINAL_PROMPT=0`，永远等不到终端输入。用系统的 Git 凭据管理器登录一次，或换成带 token 的远端地址 |
| `2002` | 本地存储失败 | 「设置保存失败」/「数据库打开失败」 | 数据目录不可写、磁盘满，或 `workbaby.db` 被别的进程占用。关掉占用者；台账损坏时会被自动挪成 `workbaby.json.bad-<毫秒>`，可在数据目录里找到 |
| `3000` | 服务商配置不合法 | 「服务商还没有填密钥」/「服务商不存在」 | 去模型页补密钥；确认服务商未被删。日志 `服务商缺密钥 code=3000` |
| `3001` | 没有可用服务商 / 模型 | 「还没有选择模型」/「之前的模型已经不存在了」 | **会自愈**：坏指针被顺手清掉（`DropActiveIf`），下一句只要去选模型即可。日志 `解析活跃模型失败 code=3001` |
| `5000` | 未绑定会话或工作区 | 「请先选择工作区」 | 文件、git、索引、对话共用这一个码。去选工作区（不是选会话） |
| `5001` | 会话文件读写失败 | 「会话文件…」 | 会话文件被删/被占用，或路径越界（必须在 `data\sessions` 下）。先切到别的会话再操作 |
| `5002` | 有任务占用引擎 | 「有任务正在跑，等它结束再…」 | 先停止当前运行，或等它结束。压缩、克隆、分叉、切会话、改名、删除正被打开的会话都会撞这个 |
| `5003` | 目标不存在 | 「分叉点不在会话里」/「没有正在进行的运行」/「没有会话可导出」 | 按 message 分：分叉点要来自这份会话的条目；插话/追加/移队需要一轮正在跑；导出需要当前有会话 |
| `7000` | 外部进程 / 上游调用失败 | 「抓取失败」/「压缩总结调不通上游」 | 网络、上游 4xx/5xx、或子进程起不来。看 `detail` 里的上游状态或 stderr |
| `8000` | 技能路径或内容不合法 | 「技能路径必须指向 SKILL.md」/「技能已存在」 | 传 `SKILL.md` 的完整路径而不是目录；换个目录名 |
| `8001` | 技能保存失败 | 「技能目录不可写」/「技能开关失败」 | 目录被占用（编辑器/杀软）、只读，或在开关项目技能。关掉占用者；项目技能在壳里不能开关 |
| `8002` | 技能删除失败 | 「只能删除技能文件，不能删除技能目录」/「项目技能请在项目内自行删除」 | 传 `SKILL.md` 路径；项目技能去仓库里删 |
| `9100` | `mcp.json` 读取/解析失败 | MCP 页出现 `read_errors` | 该文件 JSON 写坏了。手工修或删掉对应那一份；**注意引擎此时按空清单装载**（见 §2） |
| `9101` | `mcp.json` 写入失败 | 「服务名不能为空」/「未找到 MCP 服务」 | 也用于写路径校验：服务名只能字母数字下划线与短横线；条目必须存在 |
| `1404` | 未知路由 | 「未知接口」 | 前端与后端不匹配（旧前端连新后端）。重装/重启到同一版本 |
| `9999` | 未归类内部错误 | 兜底 | 读 exe 路径失败、端口监听失败、注册表写自启失败。日志里有 `业务装配失败 [9999]` 就按启动失败处理 |
| `8003` | **前端本地**：请求没拿到响应 | 「无法连接」/「请求超时」 | axios 拦截器对所有非信封失败都给这个码（`frontend/src/api/http.ts`）。后端没起来、已崩、或请求超时（客户端 600s）。注意首次启动的装配失败走的是另一条路：`getEndpoint()` 抛错 → 界面直接显示那句原话，不是 `8003`。看 `stores/app.ts` 的 `fatal` 文案与日志最后几行 |

`9102` / `9103` / `9104` **不进 HTTP 信封**，只出现在引擎侧的工具结果正文里：

| 码 | 含义 | 下一步 |
|---|---|---|
| `9102` | MCP 工具调用失败 | 服务端返回了错误。看工具卡片的输出原文与本机日志 |
| `9103` | MCP 服务进程不可达 | 服务进程没起起来或已退出。用「测试连接」验一次；确认 `command` 可执行 |
| `9104` | MCP 请求超出预算 | 单请求 30s（`mcpRequestBudget`）。条目 `timeout`（秒）可覆盖；服务太慢就调大或换服务 |

## 2. 具体症状

### 窗口不出现 / 白屏

1. 是否用 `--hidden` 启动（只上托盘，不显窗）——去托盘图标找。
2. 目录布局解析失败（数据目录不可用）会先弹一个「无法启动」的系统弹框再退出（`shell/app.go` 的 `fatalDialog`），这是唯一会用弹框报的失败。
3. 其余装配失败不弹框：窗口保持隐藏，失败原话由 `Endpoint()` 抛给前端，前端把它显示成首屏错误（`stores/app.ts` 的 `fatal`）。等满 20s 也算失败。
4. 日志找 `业务装配失败 [码]`。
5. 再查数据目录可写性（`%LOCALAPPDATA%\WorkBaby`）。

### 界面全红 / 什么都点不动（连不上后端）

`8003`。后端进程没了，或者端口被占。关掉应用重启（单实例会让第二个进程退出并把窗口唤回第一个）。
还不行就看日志尾部：端口监听失败会是 `9999`。

### 发送失败

按码分流：`5000` 没选工作区 → `3000`/`3001` 服务商与模型 → `5002` 引擎被占。
日志四个发送点：`聊天发送绑定会话失败` / `聊天发送取模型失败` / `聊天发送排队失败` / `聊天运行失败`。

### 卡在「正在回答」

1. 这一轮有没有收到收尾帧？正常路径是 `chat:settled` 紧接 `chat:done`（`Stream.Finish`）。
2. 点停止是否真的生效：`POST /chat/stop` 只 cancel，不等待。
3. 若既无帧也不停，看日志有没有 `聊天运行失败`。
4. 界面自愈手段：切走再切回会话会重拉 `/chat/state`。

### 卡在「压缩中」

压缩每次都会补 `done`：成功、总结失败、落盘失败三条出口都有（`compactNow`）。
一直不结束说明请求还挂着（同步调上游，上限 120s）。等满 120s 或停止当前运行。

### 模型下拉里有已删的模型

`GET /providers` 看 `models[]` 实际内容。原因通常是保存时 `models` 传了 `null`：
只有**非 null** 才整表对账（`Upsert`），传 null 表示「别动清单」。
删单条模型时确认 `DropActiveIf` 把指针也清了。

### 探测通过但一聊就失败

这是设计事实，不是 bug：列模型按协议走三种端点，聊天只有 OpenAI 兼容 `/chat/completions`。
见 `docs/PROVIDERS.md` §1 与 §4。要么换 OpenAI 兼容上游，要么在前面加一层转换。

### git 面板空白 / 提示不可用

`1100`：`pkg.LookPath("git")` 返回空。装 git 并确认它在 PATH（程序自己扫 PATH，不起 `where`）。

### git 操作报凭证错误

`1102`。子进程带 `GIT_TERMINAL_PROMPT=0`，任何需要终端输入的认证都会立即失败。
用 Git 凭据管理器登录一次（会落 Windows 凭据管理器），或改用带 token 的 HTTPS 远端。

### MCP 保存成功但模型没有这些工具

按顺序查：

1. 条目有没有 `command`？**url 型只进配置清单，不装载成工具**（`mcpServerDefOf` 只认 stdio）。
2. 条目是不是 `enabled: false`？缺这个键视为启用。
3. **`mcp.json` 是不是 JSON 坏了？** 读/解析失败会回 `9100` 并出现在 MCP 页的 `read_errors` 里；
   而**引擎侧的重建会把这个错误吞掉、按空清单装载**（`mcpRuntime.enabledEntries` 读文件失败直接 return，
   只记 Warn）。所以「配置页看得见、模型没有工具」最常见的根因就是文件写坏了。
   查两份：`data\mcp.json`（用户级）与 `<工作区>\.workbaby\mcp.json`（项目级）。
4. 服务进程起不来了？点「测试连接」看是真握手还是报错；日志 `MCP 服务 X 装载失败` / `已装载 N 个工具`。
5. 服务名不合法（只能字母数字 `_` `-`）会在保存时回 `9101`，不会静默。
6. 计划模式下 MCP 工具**全部被拦**：它们按写工具处理，这是预期行为。

### 索引搜不到东西

1. `GET /index/status` 的 `index_built`。切工作区后的第一次检索会惰性重建（`EnsureIndexed`），
   所以「刚切过来搜不到」是暂时的。
2. 日志 `索引完成：工作区=… 文档=…`。文档数是 0 说明该工作区没有可索引文件。
3. 索引只收文件名与符号名；找内容用 `grep` 工具，不要指望 `index_search`。
4. 重建失败只影响检索速度，不影响其它功能：它是派生数据，随时可以整体重建。

### 联网搜索不可用

1. `GET /web/status`：`web_has_key` 与 `web_message` 会直接说「去配密钥」。
2. 默认 `duckduckgo` 免密钥，能开箱用；`brave` / `exa` / `tavily` 需要密钥。
3. 抓取报 `1002` 是内网地址拦截（刻意的，不是配置问题）。
4. 抓取报 `5003`「PDF 没有抽出文字」= 扫描件，没有文字层。

### 上下文水位恒为 0 / 不显示占比

模型没填 `context_window`。窗口为 0 时只有 token 读数、没有百分比，也不会触发自动压缩
（`autoCompactionDue` 需要窗口已知）。去模型页补上窗口大小。

### 设置改了没生效

1. 界面类设置（外观）立即生效；接口类设置（服务商、模型）要重拉页面。
2. 是否被入口收敛：`/settings/save` 会把 `ui.mention_sessions` 夹到 1~20；手改文件写的坏值在读取侧再兜一次。
3. `workbaby.json` 是否被挪走过：坏文件会被改名成 `workbaby.json.bad-<毫秒>` 并从空白开始，
   所有设置回到默认。数据目录里能看到那个 `.bad` 文件。

### 数据丢失

| 丢了什么 | 能不能找回 |
|---|---|
| 会话 | **不能**。会话文件就是历史本身，删了不可重建。先在回收站/备份里找 |
| 设置 | 重设即可；`.bad-<毫秒>` 文件里可能还有原文，可以手工抄回 |
| 隐藏轮记录 | 丢了等于全部重新显示（记录在 `workbaby.json` 的 `chat.hide:` 键） |
| 技能开关 | 不受台账影响：真相是目录在哪个区。只有 `skill_toggles` 这行备注会不准 |
| 服务商与密钥 | 存在 `workbaby.db`，删掉要全部重填 |
| 索引 | 随便重建，派生数据 |

## 3. 已经收紧的边界

这些是用户能观察到的行为约束：碰到它们时不用再怀疑是 bug，按「被限制住了」理解。

| 行为 | 表现 | 依据 |
|---|---|---|
| 子进程输出每条流最多留 8 MB | stdout / stderr 各自触顶后缓冲不再增长；`bash` 结果首行标「输出超过保留上限，已截断」。命令本身照常跑完，退出码照常返回 | `pkg/proc.go` 的 `maxCapturedBytes` 与 `ProcResult.Truncated` |
| 请求体上限 16 MB | 超大 body 按解析失败处理，回 `1000`；不会先把整个 body 读进内存 | `api/server.go` 的 `maxRequestBodyBytes`（绑定前包 `MaxBytesReader`） |
| 工作区里的 junction / 符号链接逃不出去 | 路径判定同时比字符串位置与真实路径（`Inside` + `InsideResolved`）；指向工作区外的链接读写都被拒 `1002` | `pkg/fsutil.go` 的 `InsideResolved` |
| 技能正文可读不可写 | `read` 能读到已启用技能的 `SKILL.md`（在工作区之外）；`write` / `edit` 指向同一个文件被拒 | `agent/tool.go` 的 `Registry.resolve` 与 `Run` |
| MCP 每个服务的请求与应答串行 | 同一服务上的并发调用排队执行，不会互相偷走对方的应答帧 | `agent/mcp_client.go` 的 `McpClient.mu`（覆盖整个请求-等回包） |
| 慢的 SSE 订阅者会被摘掉 | 某条连接的帧队列写满就断开它，其余连接与广播不受影响；前端退避重连并用 `?since=` 补帧 | `sse/hub.go` 的 `Broadcast`（队列满即 `sub.close()`） |
| 停止会立刻杀掉子进程树 | 点停止后正在跑的 `bash` 立刻被 `taskkill /T /F` 杀掉，不等它自己的超时；杀不掉的进程树最多等 5s 就放行 | `pkg/proc.go` 的 `KillTree` 与 `killWaitBudget` |
| 停止会作废两条排队 | 排队里的话术随 `/chat/stop` 的响应原样回给界面，不会凭空消失 | `service/chat_queue.go` 的 `Chat.Stop` |
| 工作区键不能走通用保存入口 | `/settings/save` 收到 `workspace.current` / `workspace.history` 回 `1000` | `service/settings.go` 的 `reservedSettings` |
| 设置与服务商密钥在出口换掩码 | `web.search_key` 读回恒是 `••••`，服务商密钥读回恒是 `api_key_masked` | `service/settings.go` 的 `maskSettings`；`service/models.go` 的 `maskKey` |
| 模板名清洗后才落盘 | 清洗结果为空回 `1000`；保存接口回实际落盘的名字 | `service/templates.go` 的 `Save` |

## 4. 日志与定位

| 想看的 | 位置 |
|---|---|
| 当日日志 | `%LOCALAPPDATA%\WorkBaby\logs\wb-YYYY-MM-DD.log` |
| 尾部若干行 | `GET /logs?lines=`（缺省 500） |
| 设置原文 | `GET /config/text?name=settings`（白名单，不接受外部路径） |
| MCP 原文 | `GET /config/text?name=mcp` |
| 装配失败 | 日志里 `业务装配失败 [码] message detail` |

日志只写文件，不加时间戳以外的前缀；`ERROR` 级别同时写 stderr（发布版无处可看，等于只写文件）。
`Warn` 是无害记录（例如 MCP 单个服务装载失败、技能台账记账失败），
`Error` 才代表用户可见的功能受损。

前端另有一份失败现场记录（`frontend/src/utils/diag.ts`，`recordFailure`），
诊断面板里能看到最近若干条「码 + 话术 + 定位串」，对 `8003` 这类只存在于前端的问题尤其有用。
